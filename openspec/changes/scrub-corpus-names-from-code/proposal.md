## Why

为了确认产品没有为某个测试语料做特殊处理，我们审查了产品代码：从各测试语料的仓库名、包名前缀、模块名出发搜代码，再从代码里的字符串常量出发查它们只出现在哪些语料里。两个方向都没有找到按某个语料的路径、包名或类名分支的逻辑；命中的是注释里的来历说明，以及公开框架的注解目录（框架支持，对所有用该框架的项目都成立）。

但代码注释、测试与两份协作文档里仍有 22 行、1 个夹具文件名提到具体语料：注释写「在某语料上实测」「在某语料上发现」，测试用语料名当路径或文件名的例子。这些名字不影响行为，却让人读成「这段是为某个仓库写的」；而注释真正有用的是机制和规模，不是语料名。

## What Changes

- 代码注释改写成机制与规模，例如「在一个 300 万行的 Java 仓库上」「在一个真实的 TS/Vue 仓库上」，不再写语料名。
- 测试里作为例子的语料名换成中性名字；选择安全夹具里的归档文件改名为 `app-bundle.zip`。断言的含义不变。
- `.claude/agents/coder.md` 与 `deploy/selftest.sh` 里点名语料的句子改成泛称。
- 不改产品逻辑，不改 `openspec/`、`docs/` 与根目录 Markdown：那里写明在哪个语料上验过是验收证据本身，删掉就无法追溯；公开项目名没有隐私问题，私有语料早已只用代号。
- 不在仓库里加「语料名检查」测试：那样的测试本身要写进全部名字。改为在开 PR 前的本地检查里搜这些名字，名单放在仓库外。
