## Context

审查用了两个互补的方向，都不调用模型：
- 从语料到代码：取每个测试语料的仓库名、包名前缀、模块名与构件名，在产品代码（含 skill 提示词、agent、脚本、部署脚本）里按整词搜；
- 从代码到语料：把代码里的每个字符串常量拆成词，查每个词出现在哪些语料的文件名或目录名里，只出现在一两个语料里的逐个看。

结论：没有按语料分支的逻辑。剩下的只是名字，分三类：
- 注释里的来历：某个持久化格式为什么改成逐行存（在一个 300 万行的 Java 仓库上撞到了 V8 单串上限），某个 map 为什么用无原型对象（在一个真实的 TS/Vue 仓库上撞到了 `constructor` 这类词）；
- 测试里当例子的名字：归档文件名、项目目录名、注释里的数字来历；
- 协作文档里点名语料的句子：`.claude/agents/coder.md`、`deploy/selftest.sh`。

按名字扫描看不到「形式通用、实际照着某个语料调出来」的规则，例如阈值与提示词里的固定措辞。这类过拟合靠通读也难判断，放到以后的真实验收里，用开发中从没参与调试的语料去验，不在本变更里做。

## Goals / Non-Goals

**Goals:** 代码与测试里不再出现测试语料的名字；注释保留机制与规模这两样有用的信息；行为不变。

**Non-Goals:** 不改 `openspec/`、`docs/` 与根目录 Markdown；不改产品逻辑；不改 git 历史与已合并 PR 的正文。

## Decisions

### D1 注释写机制与规模，不写语料名

| 原来的写法 | 改成 |
|---|---|
| 某个公开的大型 Java 项目的名字（说明规模） | 「a 3M-line Java repository」 |
| 私有 Go 多仓库语料的代号，加「TS/Vue corpus」 | 「a real TS/Vue repository」 |
| 私有 Go 多仓库语料与它的成员仓库（说明一项手工验收） | 「a real multi-repository corpus」 |
| 一个公开 Go 示例项目的名字（说明一个计数的来历） | 「a real Go repository」 |

数字与机制原样保留（例如「66% of the runtime single-string limit」「~11ms/file」）。备选是直接删掉这些注释，没采用：它们解释了一段代码为什么这样写，删掉会丢信息。

### D2 测试里的名字换成不带语料含义的中性名字

- 选择安全夹具里的 70 字节占位归档改名为 `app-bundle.zip`，引用它的三个测试同步改。它的内容不是任何语料的代码。
- `isolatedName` 的例子要的是「名字里不含 test、fixture 的样本目录原样保留」，换成 `billing`。
- 注释里的语料名按 D1 改。

### D3 不动验收记录

`openspec/`（一百多个文件）、`docs/` 与根目录 Markdown 里写明在哪个语料上验过，是证据本身；删掉就无法追溯某个阈值或结论从哪来。公开项目名没有隐私问题，私有语料早已只用代号，所以不动。

### D4 框架名不是语料名

MAUI、Seam、TomEE、Tomahawk、PrimeFaces 等指的是框架或运行时，对所有用它们的项目都成立，保留。判据：去掉这个名字，规则是否仍然对别的项目成立。框架目录与 addendum 里的名字都满足。

### D5 名单放在仓库外

检查用的名单与命令放在仓库外：所有测试语料的仓库名、私有语料的代号、开发中给语料用过的短标签。不在仓库里加检查测试，原因是那个测试本身就要写进全部名字。每次开 PR 前，和现有的三条隐私检查一起跑。

## Risks / Trade-offs

- 换名之后，注释不再直接指向是哪次验收。需要追溯时看对应的 OpenSpec 变更（注释里已写明变更名与 design 编号），那里的记录保留了语料名。
- 名单在仓库外，别人开的 PR 不会自动检查。这是 D5 的代价。

## 验收 oracle（动手前写死）

- **O1 无残留：** 名单检查对跟踪文件（不含 `openspec/`、`docs/`、根目录 Markdown 与 `pnpm-lock.yaml`）的内容与路径都返回 0。改前同一命令返回 22 行与 1 个路径，说明装置看得见这些名字。
- **O2 行为不变：** `pnpm -r build`、`pnpm test`、`pnpm --filter @excavator/core test`、`pnpm run typecheck`、`node scripts/check-refs.mjs`、`openspec validate --all --strict` 全部通过，测试数与改前 `origin/main` 相同。
- **O3 文档、提交与 PR：** 本变更的文档、提交信息与 PR 正文用同一名单搜为 0，三条隐私检查也为 0。
