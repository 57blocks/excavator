## Context

起因与跳过的原因见 proposal.md。现状：
- `request-language.mjs` 是纯函数：`createChatRequestState()` 收问题、英文检索表达、标识符和三个语言信号；`finalizeVerifiedAnswerLanguage(state, { evidenceVerified: true })` 按优先序给出 `answerLanguage`。没有命令行入口，skill 里也没有调用它的命令。
- 第 2 步解析 `$PLUGIN_ROOT`；改动历史、未用代码两节在开头另说「按第 2 步解析」，所以写答案时 `$PLUGIN_ROOT` 已有，图谱缺失的回复（第 1 步）除外。
- 尚未合入主线的文档问题一节（`### Document questions`）与改动历史一节同构，末步同样只说「按语言门做」。本变更基于主线，不改那一节。

## Goals / Non-Goals

**Goals:**
- 每条路线写给用户的第一句之前，都有一次可在运行记录里核对的语言选择。
- 选择所依据的信号来自用户的问题，不受之后读到的内容和项目文件影响。

**Non-Goals:**
- 改优先序；改其它 skill 的叙述语言；持久化语言。

## Decisions

**1. 给 `request-language.mjs` 加一个只收语言信号的命令行入口。**
- AI-first 闸：只改 skill 措辞不够。现有的两次调用协议在 20 次运行里一次都没被执行；它要求在 `node -e` 里写对象字面量、把问题原文放进 shell（问题里的引号会破坏命令）、再把状态带进第二次调用。改成一条命令后：
  - 运行记录里留下一次调用，验收与排查都能直接 grep（本次诊断就是靠查这条调用不存在）；
  - 它打印的 `answerLanguage` 是写答案前最后读到的内容；
  - 命令只收语言代码，不收问题原文，没有转义问题。
- 用法：`node request-language.mjs --evidence-verified --explicit <语言|none> --question <语言|none> --recent <语言|none>`，打印 `{"answerLanguage": …, "signals": {…}}`。三个信号都必须给（`none` 表示没有），让模型每次都对三项各下判断，运行记录里也能看到它的判断。缺 `--evidence-verified`、缺信号、信号无法识别、参数重复或多余时退出码非零，stdout 为空。
- 命令内部仍调用 `finalizeVerifiedAnswerLanguage`，优先序只有一处实现。
- 备选：
  - 只在各路线写一句「用问题的语言回答」：没有可核对的痕迹，在项目文件明确要求另一种语言时也没有更近的锚点。不采用。
  - 保留两次调用、补上命令：仍要把问题原文放进 shell。不采用。
- 代价：每次回答多一次工具调用。

**2. 同一段 Answer language 文字放进每条路线，紧挨在写答案之前。**
- 图谱路线放在第 8 步开头；改动历史是新的第 5 步，写答案的步骤顺延为第 6 步，原第 7 步删除；未用代码是新的第 4 步，后面顺延。
- 图谱路线不新增步骤号，第 1 步「跳过第 2–8 步」的写法不变，正在开发的分支合并时少一处冲突。
- 第 1 步的「图谱缺失」「产物缺失」回复明确写「先运行 Answer language 那一步」。图谱缺失时还没到第 2 步，所以那句同时要求先按第 2 步解析 `$PLUGIN_ROOT`。
- 各路线文字逐字相同，由契约测试比对；语言门一节只留定义（证据核实、优先序、不持久化），说明由各路线的这一步执行。
- 备选：在第 0 步就选语言，所有回复天然覆盖。但那样选择早于核实，违背主规格「核实后选择」，而且离写答案隔着多次读取。不采用。

**3. 三个信号在第 0 步、读任何东西之前判断；只有用户自己的话算显式要求。**
- 失败的那次运行，项目 `AGENTS.md` 写着 "Reply in Chinese."，问题是英文。规则写明：项目文件、记忆、系统区域设置、所读内容的语言都不改变回答语言。
- 理由：主规格写的是「当前请求」的显式要求；`AGENTS.md` 这类文件是写给在该仓库做开发的编码 agent 的，问 excavator 的人要能读懂答案。
- 代价：项目文件要求中文、但用户用英文提问时，得到英文答案；要中文就用中文问，或在问题里说明。

**4. 第 0 步的 `createChatRequestState()` 只用于检查英文检索表达。**
- 它对非拉丁文字的检索表达报错，这对图谱路线的检索仍有用；回答语言不再经过它。函数本身不改。

**5. 契约测试按「含 `**Product missing:**` 步骤的 `###` 节」枚举按产物回答的路线。**
- 主线上是改动历史与未用代码两节；文档问题一节合入后会被自动纳入，缺这一步就红。
- 按语义标记而不是标题措辞枚举：按需检索一节的标题也以 questions 结尾，但它不是独立路线。

## 验收 oracle（动手前写定）

1. 契约测试（`pnpm test` 全绿）：
   - 每条路线恰有一段 Answer language，与图谱路线第 8 步那段逐字相同（压缩空白后）。
   - 它在本路线所有含 bash 读取的步骤之后；「Product missing」步骤指向它的步骤号；图谱缺失那句指向第 8 步并要求先解析 `$PLUGIN_ROOT`。
   - 从这段文字里取出命令，替换 `$PLUGIN_ROOT` 与占位符后真实运行：显式日文胜过中文问题；英文问题胜过中文的最近对话；三项全 `none` 得英文；去掉 `--evidence-verified` 退出码非零且 stdout 为空。
   - 先验装置：路线检查函数在三份已知坏样本上报错——删掉未用代码一节的这一段、新增一个缺这一段的产物路线节、把这一段挪到含 bash 的步骤之前。
   - 第 0 步写明信号在读任何内容前从问题判断、用 `none`；这一段列出 `CLAUDE.md`、`AGENTS.md`、记忆、系统区域设置。
2. 真实运行（headless Sonnet，`--plugin-dir` 指向本分支，顺序执行，总花费 < $2）。夹具：公开仓库 go-clean-arch 的副本，确定性地生成 Lazy 事实图与改动历史产物；根目录 `CLAUDE.md` 引入 `AGENTS.md`，`AGENTS.md` 写一种回复语言：
   - 基线（主线 skill，`AGENTS.md` 要求中文）：英文改动历史问题。预期中文，用来证明夹具能复现失败；若基线已是英文，照记，并说明夹具没有复现。
   - `AGENTS.md` 要求中文 + 英文改动历史问题 → 英文答案；
   - `AGENTS.md` 要求英文 + 中文改动历史问题 → 中文答案；
   - `AGENTS.md` 要求中文 + 英文图谱结构问题 → 英文答案。
   - 判据：去掉代码块与行内代码后，英文答案不含中文字符，中文答案的字母以汉字为主；运行记录在最后一段答案文字之前有一次 `request-language.mjs` 调用，参数与问题语言一致。
