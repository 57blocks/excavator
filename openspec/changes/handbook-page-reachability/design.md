## Context

真实运行的数据：功能章节的正文里绝大多数写成 `名字 (F12)`，少数写成 `名字（F12）`（全角括号，前面常是带引号的标签加「功能」二字，而不是章节标题）。系统章节的提示词规定「画一张 mermaid `flowchart LR`：各应用、存储与外部系统」，并规定了二级标题的顺序；这次运行的系统章节只有这一张图。目录（`outline`）里有几个部分不含功能章节，例如交叉主题与数据。

## Goals / Non-Goals

**Goals:** 每个功能从它的业务域页一次点击可达；技术视图一进来能看到架构；参考资料保留目录的分组；上一页与下一页能走完全部功能。

**Non-Goals:**
- 不改提示词，不加检查；
- 不让搜索覆盖数据、状态字典与代码健康三页；
- 不处理目录与业务域两种分组不一致的问题（`handbook.md` 仍按目录）。

## Decisions

### D1 正文里的功能链接

在页面的 Markdown 渲染里加一个 remark 插件，对正文的文本节点处理 `(F<n>)` 与 `（F<n>）`：
- 只处理页面有这一章的 id；不在代码、链接、标题和 mermaid 里处理；
- 前面的文字以这一章的标题结尾时，把标题变成链接，去掉 id 与括号；
- 否则只把括号里的 `F<n>` 变成链接，括号留着；
- 不链接到所在的这一页本身。

交接内容沿用现有的 `linkFeatures`（规格已写定，不动）。

**为什么不在写页面时改 Markdown**：链接的地址取决于视图，页面里已经有路由与章节标题；插件只读不改源文本，搜索的小节编号不受影响（标题不处理）。

### D2 技术视图首页的「系统架构」

页面数据 `/21` 加 `architecture: ViewTexts`：系统章节里第一个 ```` ```mermaid ```` 围栏所在的二级小节，从它的 `## ` 标题到下一个 `## ` 之前，去掉标题行，两种视图各按章节的引文规则；系统章节没有图时为 `''`。

首页只在技术视图、且这一节不空时显示：
- 标题用固定文字「系统架构」，内容全宽显示（不受 720 的正文宽度限制）；
- 下面一行列出系统章节各二级小节的链接，点了打开系统章节并停在那一节，复用搜索的跳转。

**为什么按「第一张图」找而不按标题**：标题是模型用运行的语言写的，按文字匹配不可靠；提示词规定系统章节只画这一张图，按第一张找由提示词保证。

**代价**：模型若在架构图之前多画一张图，取到的会是那一张。这时首页的这一节仍然是系统章节的一个真实小节，不会编造内容。

### D3 系统章节的导航名

导航里所有列出页面的地方（顶栏下拉、手机菜单、左栏、首页参考资料、面包屑、上一页与下一页、搜索结果）把 `system` 这一章显示成 `page.nav.system`（「System overview」）。章节页自己的 h1 仍是章节标题（产品名）。

### D4 图的全屏查看

每张画出来的图右上角有一个按钮，点开一个全屏对话框：
- 图按视口大小缩放；
- Esc 或关闭按钮关掉，焦点回到按钮；
- 对话框用 `role=dialog aria-modal`。

### D5 参考资料分组

`referencesOf` 改为返回分组：
- 目录里每个含参考资料页的部分是一组，组名是部分标题；
- 覆盖情况页单独成最后一组，没有组名；
- 只有一组时不显示组名。

顶栏下拉、手机菜单、左栏与首页参考资料都按组显示：组名是小号次要文字，组之间用分隔线，不加盒子。上一页与下一页的顺序仍是展平后的顺序。

### D6 跨域的上一页与下一页

功能页的上一页与下一页在全部组展平后的顺序里取：组按业务域（或退回时的目录部分）顺序，组内按功能顺序。跨到另一个域时，链接上方的小字写目标所在的域名。参考资料页的顺序不变。

## Risks / Trade-offs

- 全角括号前常是 `"审批"功能（F3）`，只会链接 `F3`，读者看到的是一个短链接。
- 正文里链接变多，产品视图的阅读会更花一些。只链接页面有的章节，并且不链接本页。
