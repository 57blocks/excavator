## Context

用户在本地看过并认可了功能页原型。原型的做法：
- 标签页，概览在前；
- 三级小节折叠，带一句预览；
- 直线流程改成编号步骤；
- 用 beautiful-mermaid 画图，配色柔和，按原尺寸显示。

在真实输出（72 个功能章节）上量到的事实：
- **小标题**：二级小标题的写法不统一。主流写法「概述、界面、操作、规则、状态、通知与自动行为、交接」之外还有「概览」「衔接」「页面」「与其他功能的衔接」「屏幕」等；完全符合主流写法的约 50 章。待解决问题与问题两节来自固定文字表，72 章全部一致。
- **图**：365 张 mermaid 图，其中流程图 320、状态图 45。
  - beautiful-mermaid 能画出全部 365 张。拿 Mermaid 的渲染结果对照文字，只有 1 张状态图丢了 3 个没有转换、单独成行的状态。
  - 有语法错误的源码，beautiful-mermaid 不报错，而是画出半张图。
  - 它的每张 SVG 都带一条从网络加载字体的 `@import`。
  - 节点字号 13px，边上的字 11px，没有调字号的选项。原来把高图缩进 70% 屏高，正是字看不清的原因。

## Goals / Non-Goals

**Goals:**
- 功能页先回答「这个功能能做什么、有哪些界面、交给谁」，细节折叠，一字不少。
- 小节按固定文字识别，不靠猜标题。
- 图清楚、配色和页面一致，深浅色都能读，离线可用。

**Non-Goals:**
- 不改章节的内容与引文规则，不重写已有章节。
- 不改业务域页、首页、参考资料页的版式。只有图和编号步骤对所有页面生效。
- 不改页面数据格式。

## Decisions

### D1 章节小标题来自固定文字表

- **新的键**：
  - 七个小节名：`chapter.section.overview`、`.screens`、`.operations`、`.rules`、`.states`、`.notifications`、`.handovers`，英文为 Overview、Screens、Operations、Rules、States、Notifications and automatic behavior、Hand-overs；
  - 一行固定文字 `chapter.serverSteps`，英文为「Server-side steps:」，冒号是值的一部分。
- **写作提示**：Phase 2 像打印 `$OPEN_QUESTIONS` 一样打印这八个值。`sections/features.md` 要求：
  - 二级小标题恰好用这七个值加原有两个，按这个顺序，没内容的省略（最后两个除外）；
  - 一个操作里系统内部的步骤放在最后，前面单独一行写 `$SERVER_STEPS`。
- **检查**：`chapter-lint` 对功能章节拒绝两种情况，各打印一条原因：
  - 一个二级小标题不是这九个之一；
  - 二级小标题的顺序和固定顺序不一致。
- **不影响已有章节**：只在写作的 `check` 时检查。已经通过并记录的章节，`assemble`、`page`、`reply` 不重新检查小标题，已有运行照常拼装。
- **为什么不在页面上猜标题**：同一次运行里就有 5 种以上的写法，换一种语言又是另一套。固定文字是唯一不随运行变化的锚点，而且已经有先例（待解决问题、问题）。
- **代价**：已有输出里写法不同的小节在页面上不能按角色放置（见 D3）；要完整的效果，需要用新提示词重写章节。

### D2 页面上的图

- **画法**：`beautiful-mermaid@1.1.3`（MIT）。配色取页面上的一组新 CSS 变量 `--dg-*`，浅色、深色各一套：
  - 节点：浅蓝底，淡蓝边框，深色文字。浅色下文字对底色的对比度 13:1，深色下 12:1；
  - 连线：比原配色深一档，浅色下对白底 3.1:1；
  - 边上的字：次要文字色。
- **顺序**：
  1. 用已有的 Mermaid（懒加载）执行 `parse`，不通过就显示原来的失败说明与源码；
  2. 状态图里有单独成行、只写一个状态名的行时，整张图交给 Mermaid 画。这是 beautiful-mermaid 唯一实测会丢内容的写法；
  3. 其余交给 beautiful-mermaid，并删掉输出里的 `@import` 规则，页面不发网络请求；
  4. beautiful-mermaid 抛错时，退回 Mermaid 画。
- **尺寸**：图的宽度取「原宽」与「可用宽度」中较小的一个，但不小于原宽的 85%；更宽时在图框内横向滚动。不再按屏高缩小。全屏查看保留，用同一张 SVG 的拷贝。
- **编号步骤**：`flowchart`/`graph` 方向为 TD、TB 或 LR，且同时满足下面几条时，画成编号步骤（圆形序号加连线），不画图：
  - 每个节点最多一条进、一条出；
  - 只有一个起点，全部节点连成一条；
  - 3 个节点以上；
  - 边上没有文字。

  边上有文字的不算，因为编号步骤放不下那些文字。这个规则对页面上所有 Markdown 生效。
- **代价**：模板增加约 1.6 MB（主要是 elkjs），Mermaid 仍保留，用于校验与退回。

### D3 功能页

- **哪些页面是功能页**：地图里的功能章节。系统章节与参考资料页不变。
- **拆分**：一个纯函数，在代码块之外按二级、三级小标题切开章节，得到：
  - 标题前的部分（一级标题与提示）；
  - 各小节，每节有标题、角色、开头文字，以及按三级小标题切出的各项。

  每个小标题记下它在全章二级、三级小标题里的序号 n，页面上对应元素的 id 仍是 `h-<n>`，搜索与跳转不变。
- **角色**：第一个二级小节是概述（提示词规定它在最前）。其余小节的标题等于哪个固定文字，就是哪个角色；待解决问题与问题按已有的固定文字识别。认不出的小节角色为空，照样成为一个标签页。
- **页眉**：面包屑、一级标题、标题前的提示（未核对说明等）、概述的第一段（大号字；概述不以段落开头时没有这一段）、交接条（已有组件）。
- **标签页**，依次是：
  - **概览**：概述除第一段以外的开头文字，然后依次是：
    - 「操作一览」：操作一节各项的标题与预览，点一下打开操作标签页并展开那一项；
    - 「页面一览」：页面一节各项，做法相同；
    - 交接一节的内容，前面不再重复交接条；
    - 「补充说明」：概述一节的各项，折叠显示。

    操作一览、页面一览只在那一节有三级小标题时出现。
  - **其余小节**：除概述、交接、待解决问题、问题以外的每个二级小节，按章节顺序各一个标签页，标签上带它的项数。
  - **问题**：待解决问题与问题两节，各带自己的小标题。
- **折叠**：每一项是一个折叠块，收起时显示标题与一句预览。
  - 预览取第一行不是表格、不以冒号结尾的文字，截到第一句，最多 100 个字符；
  - 有两项以上的标签页有「全部展开 / 全部收起」；
  - 操作一项里从 `chapter.serverSteps` 那一行到项末，是一个嵌套折叠块，标题是那一行去掉末尾冒号；
  - 标签页面板用 `hidden="until-found"`，监听 `beforematch` 切换标签页，所以查找能找到收起的内容。
- **跳转**：搜索结果或链接指向某个小标题时，选中它所在的标签页，展开它所在的项，滚动并聚焦。功能页不显示右侧目录，标签页取代它。
- **手机**：标签页横向滚动，没有页面级横向滚动。
- **固定文字**：`page.feature.overview`（概览）、`.canDo`（操作一览）、`.screens`（页面一览）、`.more`（补充说明）、`.issues`（问题）、`.expandAll`、`.collapseAll`。
- **代价**：读者第一眼看不到全部内容，要点开；查找、搜索与「全部展开」保证内容都能到达。

### D4 用词

用户审读了页面上的固定用词。以下几处在英文固定文字表里改掉，各语言的翻译随之改变。

- **交接的方向统一成上游与下游**。原来同一个概念有三套说法：交给/来自、交出/接手、交接。「交接」只留作关系本身的名字。

  | 键 | 英文 | 期望的中文 |
  |---|---|---|
  | `page.handover.out` / `.in` | Downstream / Upstream | 下游 / 上游 |
  | `page.table.hands` / `.receives` | Downstream domains / Upstream domains | 下游业务域 / 上游业务域 |
  | `page.flow.out` / `.in` | Downstream ({count}) / Upstream ({count}) | 下游（{count}）/ 上游（{count}） |
  | `page.flow.counts` | {in} upstream, {out} downstream | 上游 {in}，下游 {out} |
  | `page.map.legend.out` / `.in` | downstream / upstream | 下游 / 上游 |
  | `page.map.legend.centre` | dashed box: no upstream domain | 虚线框：没有上游 |
  | `page.map.hint` | Choose a domain to see its upstream and downstream domains, or a line to see one hand-over. | 选择一个业务域查看它的上游与下游，选择一条连线查看这一条交接 |
  | `page.map.edge` | {from} → {to} | {from} → {to} |
  | `page.handover.between` | → | → |
  | `page.domain.noneIn` / `.noneOut` | No upstream domain. / No downstream domain. | 没有上游业务域。/ 没有下游业务域。 |

- **章节的最后两节与「无」**：

  | 键 | 英文 | 期望的中文 | 理由 |
  |---|---|---|---|
  | `chapter.openQuestions` | Points to confirm | 待确认事项 | 写的是代码定不下来的点；不再和下一节撞名 |
  | `chapter.problems` | Known defects | 已知缺陷 | 写的是能复现的缺陷 |
  | `chapter.none` | None. | 无。 | 放在待确认事项下面也通顺 |

- **其他**：
  - `page.table.what` 改成 Responsibilities，中文「职责」，因为列名用名词；
  - 小节名 `chapter.section.screens` 改成 Pages（页面），概览的 `page.feature.screens` 改成 Pages at a glance（页面一览），因为读者说「页面」，「界面」偏设计与开发用语。
- **已有运行**：已有运行的 `ui.json` 保留原来的译文。`check-ui` 只查键是否齐全，不查值，所以它的 `chapter.*` 仍和它的章节一致，页面照常认得出最后两节。只有新运行会用新名字。验收时只给已有输出补新键，并改掉只在页面上出现的用词（交接方向、职责），不改 `chapter.*` 的值。

## Risks / Trade-offs

- **已有输出的部分小节认不出**：真实输出约 22 章至少有一节写法不同。这些小节各成一个标签页，概览里少了对应的列表，内容不丢。验收时如实统计。
- **beautiful-mermaid 还可能有没测到的丢内容写法**：验收时在真实输出的全部图上，对照 Mermaid 渲染的文字做一次覆盖统计，照实记录。
- **模板变大**：页面仍是可以直接打开的单个文件；模板大小检查如有上限，验收时记录实际值。

## Migration Plan

已有运行重新跑 `page` 即可。要完整的标签页效果，可以用新提示词重写功能章节，这不在本变更内。
