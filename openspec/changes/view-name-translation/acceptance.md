## 真实运行

语料：每个 PR 的机制冒烟语料，一个 49 个文件的 Go 后端服务，用 `node-display-name` 验收时的完整分析产物（229 个节点带显示名）的副本；先在副本上跑领域分析（$0.43，3 个领域、7 个流程、26 个步骤），再导出。导出用 `--out` 写到语料外，Sonnet。

| 运行 | 插件 | 用时 | 花费 | 翻译子代理派发 | 结果 |
|---|---|---|---|---|---|
| 第一次导出 | 修复前 | 61 秒 | $0.35 | 3（2 批 + 1 次重派） | 242/244 译出，2 条两轮都丢了 `URL`，保留英文 |
| 第二次导出 | 修复前 | 41 秒 | $0.19 | 2 | 242 条全部复用，翻译表逐字节不变；那 2 条又被派了两次 |
| 新表第一次导出 | 修复后 | 49 秒 | $0.32 | 2（2 批，无重派） | 244/244 译出 |
| 新表第二次导出 | 修复后 | 21 秒 | $0.13 | 0 | 244/244 全部复用，翻译表逐字节不变 |

- 判据 1：两次首轮导出的计数都守恒（242 + 2 = 244；244 + 0 = 244），保留英文的条目在页面与回复里可见；工作目录在结束时删除；语料的 `.excavator/` 下没有新文件。达标。
- 判据 2：修复前未达标。第二次导出把两轮都被拒绝的 2 个名称当作缺译重新派发，每次导出都会重试。修复：第二轮仍不过的名称以拒绝记录写进翻译表，英文不变时不再列出；批文件的每条名称带上它必须保留的代码记号（`keep`）。修复后从空表重跑，第二次导出没有派发子代理。达标。
- 判据 3：固定种子分层抽 30 条（节点显示名 20、领域与流程与步骤名 10），主会话逐条判断，修复前后两张表各判一次，错译均为 0/30。`Authorization code grant` 两次分别译作「授权码许可」「授权码授权」，都可接受；同一段英文在两次运行间译法不同，这是按英文原文索引、复用首次译文的原因。达标。
- 判据 4：244 个名称的翻译加导出共 $0.32 到 $0.35（每次导出本身约 $0.13）；每批最多 200 条（244 条分为 200 与 44 两批），每批一次子代理派发。按此估算，名称数每增加 200，首次导出约多一次派发。

## 局限

- 拒绝记录只有单元测试：修复后的真实运行里没有名称被拒绝，`keep` 让原先丢 `URL` 的 2 条一次通过。
- 判据 3 只抽了 30 条、一种目标语言、一个语料；译文是否“产品化”没有量化判据，只核对了不译错。
- 只在 `--out` 写到语料外的方式下跑过真实运行；默认写到 `.excavator/` 的路径只有单元测试。

## 评审第一轮之后

评审（2 Important、3 Nit）后的改动，每处先写用例、在改动前的代码上为红：

- 结果里有批文件没有的键时整批失败：原来只记一次 `extra-key`、照样合并其余键，序号整体错位（从 0 编号）时每个名称会拿到另一个名称的译文并通过核对。这是任务卡与 design「键一一对应」的不一致。
- 子代理两轮都没写出结果（`no-result`）不记为拒绝，名称本次保留英文、下次导出重派；其余原因仍记为拒绝。
- 含 `_` 或 `.` 的标识符（`user_id`、`payment_v2`、`Node.js`）整体算作代码记号；连字符仍拆开。
- `en_` 开头的语言名算英文。
- PR 正文补上 How to revert 一节与“这些检查漏掉什么”。

变异：多键不再整批失败、`no-result` 记为拒绝，2 处都使用例变红。受影响范围 47 个文件、887 条用例通过；explorer 包 390 条通过；短 `TMPDIR` 下翻译用例 154 条通过。
