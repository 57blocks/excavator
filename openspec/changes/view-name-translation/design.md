## 决定

### 1. 翻译在导出时做，存在页面旁边

翻译表写在 `<页面所在目录>/view-translations/<lang>.json`：默认页面在 `.excavator/`，表就在 `.excavator/view-translations/`；给了 `--out` 时跟着页面走，`.excavator/` 不被写。`/excavator-view` 原有的“除页面外不改 `.excavator/` 下任何文件”改为“除页面与它的翻译表外”。

不写进语义缓存或领域图：规范产物只有一种语言，核验、新鲜度和检索都只认它。译文是表现层的派生物，丢了可以从英文重新翻。

### 2. 按英文原文的哈希索引

表的形状：`{format: "excavator-view-translations/1", language, entries: {<sha256(英文)>: {en, text}}}`。

- 同一段英文（两个节点同名、重新分析后名称没变）只翻一次；
- 英文变了哈希就变，旧译文不再被取用，不需要新鲜度逻辑；
- `en` 原文随条目存下，核对时比对哈希与原文，防止表被手改后错配。
- 代价：同一段英文在不同节点上只有一种译法。名称是 2 到 8 个词的短语、带着动宾结构，歧义少；验收抽查若发现同名异义的错译，再按“英文加节点种类”索引，不预先加。

语言名由本 skill 自己规范化，不引用其他 skill 的代码：去掉首尾空白、转小写；`en`、`english` 与以 `en-` 或 `en_` 开头的名称算英文，英文时不翻译、不读不写翻译表。其余名称只许字母（任何文字）、数字、`-`、`_`，因为它直接作翻译表的文件名，含路径分隔符等字符时报错退出。

### 3. 列名称、翻译、核对、打包分开

- `translations.mjs plan`：读页面将要显示的名称——新鲜且未判 `contradicted` 的语义条目的 `displayName`、节点自己的 `displayName`（图模式路径）、领域图里 `domain`、`flow`、`step` 节点的 `name`——去掉翻译表里已有的（含拒绝记录的，见 `check`），按每批最多 200 条写出批文件。名称取自打包自己构建的页面数据（同一个函数），所以列出的就是页面会显示的。没有待译名称时不派子代理。
- 批文件与结果文件放在 `<页面所在目录>/view-translations/work-<lang>/`：`plan` 先清空再写；批文件里每条名称用批内序号（`1`、`2`……）作键，并记下它的哈希与原文，子代理只需照抄短序号；每条另带 `keep`（原文的代码记号数组，可为空，供子代理对照；`check` 自己重算、不信批文件）；最后一次 `check` 后目录被删除。
- 子代理 `excavator-view-translator`：只读一个批文件，只写对应的结果文件 `{<key>: <译文>}`。它不读源码、不读产物、不读翻译表；工具只有 Read 与 Write。提示词写明：给不读代码的人看；保留代码记号；不加解释、不加标点；不懂的词按字面译，不编含义。
- `translations.mjs check`：核对每个结果文件后把通过的条目并进翻译表（临时文件加改名）。第一轮失败的条目写成重派批文件并打印出来，skill 再派一次子代理、再跑一次 `check`；第二轮仍失败的留给英文，并以 `{en, refused: <原因>}`（无 `text`）写进翻译表（`no-result`，即子代理没有写出结果，不记为拒绝：该名称本次导出仍是英文，下次导出重派），与同批合并的译文一次原子写出；表里读到这样的条目（键为其 `en` 的哈希）算拒绝记录，不算对不上，`plan` 不再列出该名称，打包把它计入 `refused` 并仍算退回英文，英文变了哈希就变，才会再派；删掉表项或整张表则重派。没有待重派的批次时删除临时目录。
- `pack.mjs --language <lang>`：只读翻译表，不调模型。页面数据多一个键 `name-translations.json`：`{language, names: {<英文>: <译文>}, counts}`，只列页面要显示、且表里有合法译文的名称；知识图与领域图的数据不变。页面显示名称时查这张表，有译文用译文，否则用英文。manifest 记下名称总数、译出、退回英文、与英文相同、表里对不上（哈希与原文不符）和表里已不再用到的条数。

打包保持零模型：翻译步骤由 skill 在打包之前编排，只有给了 `--language` 才发生。

### 4. 确定性核对

每条译文：

- 是字符串，去掉首尾空白后非空，单行；
- 最多 60 个字符，且不超过英文原文字符数的 2 倍再加 10（防止写成解释）；
- 英文原文里的代码记号——含 `_` 或 `.` 的标识符（`user_id`、`config.yaml`、`Node.js`）、含数字或连续大写字母的词（`OAuth2`、`CORS`、`PKCE`）、全大写的 HTTP 动词、反引号里的内容——在译文里逐字出现；
- 键与批文件一一对应：缺键记为该键失败；结果里有批文件没有的键时整批失败（每条记为 `extra-key`、该批一条也不合并），不猜。

不做目标语言的语言审计：目标语言任意，没有可靠的确定性判据；与英文原文完全相同的译文允许（专有名称本来不译），算作译出，另在 manifest 与概览里计数。

### 5. 页面怎样显示

- 节点卡片：主标题是译名，副标题仍是代码名（与 `node-display-name` 一致）。
- 节点详情：在名称下写 `English: <原文>`，并标明是机器翻译。
- 领域图的领域、流程、步骤：显示译名，悬停与详情里给英文原文。
- 概览：写一行“名称经机器翻译成 <语言>：译出 N 条，M 条保留英文”。
- 搜索：同时匹配译名与英文原名。
- `contradicted` 的名称本来就为空，不翻译也不显示。

这是对副本的又一处改动，写进 `离线仪表盘` 的改动清单。译名放在单独的译名表里、不改图的数据，所以该要求「填入的数据只改形状、不改内容」仍然成立。

### 6. 回复

给了 `--language` 且不是英文时，在固定五行之后加第六行：
`Translation: <语言> <译出>/<总数> names (<退回英文> in English)`。
其余五行与回复语言不变（仍为英文），不因 `--language` 改变。

### 7. 不另设核验子代理

名称是短语，确定性核对已挡住最常见的失败（写成句子、丢代码记号、漏条目）。语义是否译对，由验收时分层人工抽查判断；不达标再加核验，不预先加。

## Oracle（动手前写死）

**先验装置：** 下列每条新用例先在旧代码上跑，确认为红，记进 `acceptance.md`。

1. 不给 `--language` 与给 `english` 时写出的页面逐字节相同；页面内联的数据与 manifest 与改动前的打包结果相同（模板会因本变更重建，所以不比整页字节）；两种情况都不创建 `view-translations/`。
2. `plan` 列出的名称恰是页面要显示的名称减去翻译表已有的；`contradicted` 与不新鲜条目的名称不在其中；两个节点同名只列一次。
3. `check`：缺键、多键、空串、换行、超长、丢 `OAuth2` 记号、丢 `GET`，各一条，分别落进对应的失败原因，不进翻译表；合法条目进表，表按临时文件加改名写出。
4. 翻译表里 `en` 与哈希不符的条目不被取用，并计数。
5. `pack --language zh`：页面数据里的知识图与领域图与不给 `--language` 时相同；`name-translations.json` 只列页面要显示且有合法译文的名称；有译文的节点卡片主标题是译文、详情写出英文原文；没有译文的退回英文；manifest 的计数与表一致。
6. 给 `--out` 时翻译表写在页面旁边，`.excavator/` 下没有新文件。
7. 回复第六行的形状与计数取自页面 manifest。
8. Chat、MCP `recall` 与核验的代码不引用 `view-translations`（文本扫描测试）。

**真实运行：** 每个 PR 的机制冒烟语料（49 个文件的 Go 后端服务），在 `node-display-name` 合并后的完整分析产物上：

- 判据 1：`--language zh` 一次导出，名称全部译出或可见地退回英文，计数守恒（译出 + 退回 = 总数）；
- 判据 2：再导出一次，不派翻译子代理（全部复用）；
- 判据 3：分层抽 30 条（节点显示名 20、领域与流程名 10），人工判断译文是否与英文同义，错译为 0；
- 判据 4：记录翻译花费与条数，作为大项目的估算依据。

判据 3 不达标时照实记下，再决定是否加核验步骤，不挪阈值。
