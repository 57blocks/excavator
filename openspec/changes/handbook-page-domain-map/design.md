## Context

- 手册由 `handbook-skill-first` 改成散文章节：每章是一份带引文的 Markdown，`check` 统一核对，`page` 把章节 Markdown 与脚本的 JSON 放进页面数据（`/19`），模板 `packages/product-handbook-page` 渲染。
- 「领域」一章由一个写作子代理只读已写好的章节写成，里面有业务域列表、域间交接的表格、每个域一节（说明、功能表、交接列表、主线流程图）。
- 设计依据：本会话做过一个可点的原型，用一次真实运行的输出验证了版式。设计简报的要点（地图是唯一的主角，颜色只编码业务域与方向，其余安静）写在下面 D5 到 D8。

## Goals / Non-Goals

**Goals:**
- 页面能画出业务域之间的关系，数据来自脚本核对过的结构化清单，不解析模型的表格。
- 一套新的版式与视觉，覆盖首页、业务域页、功能页与参考资料页，手机与深色模式可用。

**Non-Goals:**
- 不改数据、状态字典、代码健康三页的内容与组件结构，只换样式变量。
- 不改 `handbook.md` 与 `handbook-technical.md` 的拼装。
- 不为没有 `domains.json` 的旧运行从 Markdown 里推出交接。

## Decisions

### D1 交接清单由写「领域」一章的子代理一起写

`domains.json` 的形状：

```json
{
  "domains": [{ "name": "<与二级标题相同>", "features": ["F1", "F2"] }],
  "handovers": [{ "from": "<域名>", "to": "<域名>", "what": "<一句读者文字>", "cites": ["<路径>:<起>-<止>"] }]
}
```

- 只写业务域之间的交接，`from` 与 `to` 不同。域内的交接只在章节里。
- `what` 里功能写成「名字 (F12)」，与章节的写法一致，页面据此做链接。
- 不另写说明文字：域的说明取自章节本域那一节的第一段（D3），避免两份文字不一致。

**为什么不由脚本从表格里解析：** 表格是模型写的，列名、合并单元格、续表的写法每次都可能变。让模型直接写结构，由脚本核对结构，与手册其余部分的分工一致（模型写、脚本核）。

**为什么不另开一个子代理：** 同一个子代理刚写完这一章，交接就是它自己写的那些行，另开一个要重新读一遍所有章节。

### D2 `check domains` 一起核对清单

在现有的章节核对之后，名字是 `domains` 时再核对 `domains.json`，规则见规格。问题与章节的问题合在一起，算作这一章没通过，重写时一起改。

- 引文只核对「原样出现在 `domains.md` 里」，不重新解析到源码：`domains.md` 自己的引文已经被同一次 `check` 解析过。
- 通过时在 `state.json` 这一章的记录里加 `json`：`domains.json` 的 sha256。页面据此判断清单是不是检查过的那一份。
- `state.json` 的格式串不变（`/2`）：新字段只在 `domains` 的记录里出现，旧记录没有它，按「没有核对过的清单」处理。
- 续跑时，`domains` 的记录是 `passed` 却没有 `json` 的，算作还要写：第 8 阶段的第 2 步照「没有文件也没有记录」处理，删掉旧章节后重写。这样旧运行用 `--sections domains` 再跑一次就能补上清单，不用手工删文件。

### D3 页面数据 `/20`

在 `/19` 上加：

```ts
domains: {
  state: 'ok' | 'missing' | 'failed' | 'changed';
  list: { id: string; name: string; features: string[]; intro: ViewTexts; body: ViewTexts }[];
  handovers: { from: string; to: string; what: string; features: string[]; cites?: string[] }[];
};
lead: string;
search: { title: string; chapter: string | null; domain: string | null; heading: number | null; kind: 'domain' | 'chapter' | 'heading' }[];
```

- `state`：
  - `ok`：记录通过、摘要相同、文件能读；
  - `missing`：没有文件或没有记录；
  - `failed`：这一章没通过；
  - `changed`：摘要不同。

  非 `ok` 时 `list` 与 `handovers` 都是空数组。
- `id` 按顺序是 `d1`、`d2`……，交接里的 `from`、`to` 用 id。
- `intro` 与 `body`：从 `domains.md` 里切出本域那一节（以等于域名的二级标题开始，到下一个二级标题为止），去掉标题，第一段是 `intro`，其余是 `body`。两种视图按章节的同一套规则处理引文（产品视图去掉）。
- `features`：交接内容里「(F12)」形式且在地图里的 id，按出现顺序去重。
- `cites` 只在页面有技术视图时出现。
- `lead`：系统章节产品视图文本的第一段，没有系统章节时为空串。
- `search`：
  - 每个域一项；
  - 目录里每章一项；
  - 每章产品视图文本里每个二级、三级标题一项，`heading` 是这一章里第几个二级或三级标题（从 0 起），与页面给标题编号的顺序一致。

  索引放在页面的主数据里，拆成多个数据文件时也在。

### D4 路由与页面结构

- 路由：
  - `#/` 是首页（地图）；
  - 新增 `#/domain/<id>`；
  - 章节、数据、状态字典、代码健康与覆盖的路由不变；
  - 两种视图时照旧在前面加视图。
- 分组：
  - `domains.state` 为 `ok` 时，功能章节按域分组；
  - 否则按目录里含功能章节的部分分组，分组的 id 也是 `d1`……，名字是部分名。
- 参考资料：目录里不是功能章节的各块，加上覆盖，按目录顺序。
- 阅读页：
  - 左栏是所在分组；
  - 右栏是本页目录（二级、三级标题，跟随阅读位置）；
  - 页末的上一页与下一页在同一分组里。

### D5 地图

布局由一个纯函数算出，输入是域的顺序与交接，输出是每个域的位置、颜色序号和每条通道的路径：
- **中心**：没有接手、交出最多的域，交出至少 1 条；并列取靠前的。
- **环上的顺序**：从章节顺序出发，反复交换任意两个位置，只要能减少「每条交接两端在环上的距离之和」就交换，直到不能再减少。全程确定，没有随机数。
- **通道**：二次曲线，控制点向中心收，双向的一对各向一侧偏开；通道在框边截断，带箭头。
- **颜色**：12 种低饱和的地层色按环上的位置分配（中心是中性灰），超过 12 个域时循环。

选中、悬停与键盘的行为见规格。宽度小于 900px 时不画地图，改为交接列表。

**为什么不用力导向布局：** 每次排布都不一样，看起来像一团线；环形是确定的，像一张勘察平面图。

### D6 视觉

- **颜色**（浅色 / 深色）：

  | 用途 | 浅色 | 深色 |
  |---|---|---|
  | 正文 | #1C2430 | #E6E9EE |
  | 次要文字 | #59636F | #A4ADB8 |
  | 页面底色 | #FAFAF9 | #12161C |
  | 分隔线 | #D9DDE2 | #2A313B |
  | 唯一强调色：链接、选中、交出 | #1F4FA3 | #8FB1F2 |
  | 接手 | #A8661A | #E3A85F |

  深色模式下地层色与底色按 40% 混合。
- **字体**：
  - 拉丁字母与数字用 IBM Plex Sans 400/500/600/700，等宽用 IBM Plex Mono 400/500，都打包进模板（`@fontsource` 的 latin 子集，OFL）；
  - 中文用系统字体。
- **字号**：首页标题 36，章节标题 30，二级 21，三级 17，正文 16，行高 1.75 到 1.8。
- **盒子**：最多一层。地图是唯一带边框的大块；业务域与参考资料用表格和带分隔线的列表，不用卡片网格。
- **不用**：大数字统计卡、全大写小标签、「A · B · C」式的点分元信息。
- **交互**：
  - 焦点可见；
  - 动效 120 到 160ms，尊重「减少动态效果」；
  - 表格自带横向滚动；
  - 手机宽度没有页面级横向滚动。

### D7 固定文字

页面新增的文字全部是 `ui-strings.json` 里的 `page.*` 键，英文随技能发布，其他语言由翻译固定文字的步骤写进 `ui.json`。不再用的 `page.*` 键删掉。旧运行的 `ui.json` 缺新键时，`page` 照现有规则拒绝，提示重新翻译固定文字。

### D8 实现分两步

先做技能一侧（提示词、核对、页面数据 `/20`），再重写页面。页面重写时：
- 数据、状态字典、代码健康三页的组件保留，只换样式变量；
- 其余组件按新结构重写，测试随之重写。

## Risks / Trade-offs

- [模型漏写或写错 `domains.json`] → 核对失败按「重写一次」处理；两次都没通过时页面退回按目录分组，并写明原因，不会画出没核对过的关系。
- [域很多时环上拥挤] → 椭圆的大小随域数增长，并限制标签的宽度；超过 16 个域时的可读性没有验证过，作为局限写进验收记录。
- [交接集中在几个相邻的域时，箭头在框边重叠] → 通道在框边截断、双向偏开；原型里能看清，残余的重叠写进验收记录。
- [旧运行要重写「领域」一章才有地图] → 只需 `--sections domains` 再跑一次，不重写功能章节。
- [字体使模板变大约 150KB] → 只打包 latin 子集的 6 个字重。

## Migration Plan

- 合入后，已有的输出目录要做两件事：
  1. 重新翻译固定文字（新键）；
  2. 用 `--sections domains` 重写「领域」一章，才有地图。

  不做也能出页面，只是没有地图。
- 回退：按 commit 逐步 revert，页面数据格式与模板一起回退。
