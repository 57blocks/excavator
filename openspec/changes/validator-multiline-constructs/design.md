## Context

动机与数字见 proposal。现状：`validate-graph.mjs` 对锚点在 `lineRange[0]` ±1 行找名字；对抽取器写的证据，除 `imports` 外都只看证据行本身（`imports` 已按整条语句扫描，`findTokenInImportStatement`，是本变更沿用的先例）。

逐条对照真实冒烟（74 文件 Java 子项目，tree-sitter 事实图，`full` 运行后由独立复核写出的 `validation.json`）：

| 类 | 条数 | 名字距证据行 | 机制 |
|---|---:|---|---|
| `contains` 边 | 530 | 1 行 450 / 2 行 73 / 3 行 5 / 22 行 2 | 证据行是成员范围的起点 = 注解 |
| `exports` 边 | 242 | 1 / 2 / 3 / 22 行 | 同上 |
| `implements` 边 | 40 | 1 行 | 同上（`@Override`） |
| `overrides` 边 | 10 | 1 行 | 同上 |
| 锚点 | 47 | 1–2 行；个别类的注解块更长 | `lineRange` 从注解开始 |
| `calls` 边 | 50 | 1 到 11 行 | 表达式跨多行（链式、builder） |

另有 74 条结构问题（文件节点不在任何层）与 `project.model` 为空，二者来自语义阶段被预算跳过，不属于本变更。

AI-first scope gate：这是机器校验器本身的判定规则，要确定性复用，没有 skill / prompt 的替代；改的是校验器宽严，不是新增抽取。

## Goals / Non-Goals

**Goals:**
- 上表六类在真实冒烟图上归零，且归零不靠放宽到错位也能通过。
- 校验器仍然看得见已知假样本（错位锚点、指向无关语句的证据行、改错名字的边），宽容只给抽取器写的证据。
- 越界结果可见：过长的结构不静默放过也不误报。

**Non-Goals:**
- 不改抽取器、不改 `lineRange` 与证据行的定义；不改 `EXCAVATOR_MAX_CONTRADICTED` 与 `deploy/`。
- 不引入语言解析器或按语言分支；不处理预算与语义阶段被跳过的问题。

## Decisions

**D1　改验证器，不改抽取器。** tree-sitter 的范围包含注解是该语言的真实声明边界，证据行取成员范围起点也是一致的约定。把抽取器改成指向名字行会动事实摘要、快照、`source-index` 与全部下游测试，而且抽取器写的是对的。验证器才是过严的一侧。备选「让抽取器同时写名字行」被否决：多一个字段，所有消费者要同步，收益只是验证器少一点文本规则。

**D2　按结构跳前导行，不放宽固定窗口。** 距离最远 22 行（一个含嵌套注解、字符串字面量里带 `@` 与 `\n` 的注解块，已在真实源码里核实），若把 ±1 改成 ±25，一个错位 20 行、落进别的声明里的锚点会被确认，验证器就看不见错位了。改成：从 `lineRange[0]` 向前，越过空行、注释、注解 / 装饰器 / 属性（含参数跨行）；停在第一行不是这些的行，名字必须在这一行。落在方法体或别的声明里的错位不是前导行，跳不过去，所以仍被报出。

前导行的文本规则（语言无关，不做解析）：
- 空行；`//`、`#`、`*` 开头、`/* … */` 块（含块内各行）的注释行；
- 以 `@`（Java / Kotlin / TS / Python / Swift）、`#[`（Rust）开头的注解行，或形如 `[Name(` / `[Name]` 的属性行（C#）；这一行的括号 `(`、`[`、`{` 按配平计，字符串字面量内的括号不计，直到配平后才算这条注解结束，所以多行参数块整体被越过；
- 注解之后同一行还有声明（`@Override public void f()`）的情形由原有的起点 ±1 判定承接，所以新规则是原规则的并集，不会让原来通过的变成不通过。

**D3　类型无关：证据行也先试原行，再试跳前导行。** `contains` / `exports` / `implements` / `overrides` 的证据行都是成员范围的起点，名字在跳过注解之后的声明行上。不按类型枚举（类型集合随抽取器增长，漏一个就是静默误报），而是对所有抽取器写的证据先试原行（保留 `routes` / `contains` 到端点这类「证据行就是注解本身」的现有语义），再试跳过前导行之后的那一行。

**D4　`calls` 按整条表达式核对，只对抽取器写的证据。** 证据行是表达式起点，被调用者名字在后。表达式边界：顶层（括号深度 0）的 `{` 是块体（函数体、分支），到此结束，不并入表达式——否则指向 `void m() {` 的错边会被体内任何一次调用确认，已知假样本（证据行指向声明行）就看不见了，这是实施时由既有的先验装置门禁发现的；括号里的 `{`（lambda、匿名类）不受影响，所以 `.map(x -> {…}).collect(…)` 的 `collect` 仍能找到。括号配平；行尾为 `.`、二元运算符、`,`、`->`、`\`，或下一个非空行以 `.`、`?.`、运算符开头，则续行；到顶层 `;` 结束；括号深度回到 0 且无续行时在该行结束。覆盖链式调用、builder 链、长参数列表。每行先查 token 再判是否结束（沿用 `imports` 的做法），所以不会越过含 token 的行再走远。

`source: "model"` 的证据不享受这条：模型写的引用是不可信输入，只核对被引用的那一行，与 `imports` 的现状一致。因此新宽容不可能被模型构造出来的内容触发。

**D5　上限是一个可见的桶，不是悄悄放过。** 注解块或表达式超过扫描上限（常量 `CONSTRUCT_SCAN_LINES = 400`）仍没有结束时，节点 / 边标 `unverified`，计入新缺口 `construct-too-long`，既不确认也不算 contradicted；没有「不知道算过」的第四态。上限只在抽取器写的证据上可达（模型引用不走扫描），所以上限不能被用来让一条虚构的边「过关」；它只会让一条真实但极长的结构显示为未核。代价：一条真实边落进 `unverified` 而不是 `confirmed`，计数可见。400 来自：真实冒烟里最长的合法前导 / 表达式是 22 行，留一个数量级的余量，同时把单条边的最坏扫描成本压在常数内。

**D6　改动的数据流。** 抽出两个纯函数 `skipLeadingLines(reader, file, line)` 与 `findTokenInExpression(reader, file, line, tokens)`，返回「行号 / 过长 / 无」三态；锚点与证据两处各自调用，`validateAgainstSource` 的结构不变。报告多一个计数 `constructTooLong`（0 时不出缺口，与现有计数同口径）。SKILL.md 的 Phase 6b 检查说明改一处散文。

## Risks / Trade-offs

- **[精度下降：同一语句内同名的另一次调用会让一条错边被确认]** → 只给抽取器（tree-sitter）写的证据；在 scratchpad 克隆里植入「指向相邻语句」「改错被调用者名」的假边，要求全部仍为 contradicted（见 tasks 5.2）；模型引用的证据不变。
- **[表达式扫描会越过 lambda / 匿名类的块体：指向 `submit(() -> {…})` 这类语句的错边，若 callee 恰好是块内的另一次调用，会被确认]** → 不能改成「遇 `{` 即止」：`list.stream().map(x -> {…}).collect(…)` 的 callee `collect` 在块之后，那样会把大量真边误判。接受这一精度代价，并在 5.2 里专门植入「证据行指向含 lambda 块的语句、callee 是块内另一次调用」的假边，记录其中被确认的比例；若不为零，如实写进验收记录并列为已知残余，不事后挪规则。
- **[错位锚点落在纯前导行里（注释、注解）会被确认]** → 这与抽取器对被注解声明给出的范围无法区分，是 D2 的固有边界；错位进方法体或别的声明仍被报出，测试钉死。
- **[文本规则漏掉一种前导 / 续行写法，单种写法零掉一整类]** → 每种写法一个夹具（Java 注解、多行注解块、TS / Python 装饰器、C# 属性、Rust 属性、行尾 `.` 与行首 `.` 链）；真实冒烟图逐类归零作为验收，不以夹具全绿代替。
- **[`#` 既是 Python 注释又可能是别的语言的前缀]** → 前导行里的 `#` 只越过「整行是注释」的行；`#[` 单独按 Rust 属性配平；不让 `#include` 之类越过——它们不是 `lineRange` 的起点，错位落到那里仍被报出。
- **[400 行上限的 `unverified` 被误当作「通过」]** → `unverified` 不进 `edge-contradicted`，但缺口 `construct-too-long` 带计数与样例；验收记录要写该计数。

## Migration Plan

校验器是纯函数加一个 CLI，输出字段只增不减（`counts.constructTooLong`、缺口 `construct-too-long`）。旧产物重新验证即可得到新结果，无数据迁移。回滚就是还原 `validate-graph.mjs`；旧阈值与 `deploy/` 未动。
