## Context

动机与数字见 proposal。现状：`validate-graph.mjs` 对锚点在 `lineRange[0]` ±1 行找名字；对抽取器写的证据，除 `imports` 外都只看证据行本身（`imports` 已按整条语句扫描）。

逐条对照真实冒烟（74 文件 Java 子项目，tree-sitter 事实图，`full` 运行后由独立复核写出的 `validation.json`）：

| 类 | 条数 | 名字距证据行 | 机制 |
|---|---:|---|---|
| `contains` 边 | 530 | 1 行 450 / 2 行 73 / 3 行 5 / 22 行 2 | 证据行是成员范围的起点 = 注解 |
| `exports` 边 | 242 | 1 / 2 / 3 / 22 行 | 同上 |
| `implements` 边 | 40 | 1 行 | 同上（`@Override`） |
| `overrides` 边 | 10 | 1 行 | 同上 |
| 锚点 | 47 | 1–2 行；个别类的注解块更长 | `lineRange` 从注解开始 |

这 869 条属本变更。其余 50 条 `calls`（表达式跨多行）与 4 个折行声明头、它们的 16 条边，属 `validator-multiline-calls`。

另有 74 条结构问题（文件节点不在任何层）与 `project.model` 为空，来自语义阶段被跳过或运行器按旧布局检查，不属本变更。

此前同一件事曾作为一个合并的变更评审过三轮（锚点、前导行、折行声明头、`calls` 表达式、边都在里面）。前两轮的重要问题都出在文字启发式里（把一行语句当成折行声明头、把行尾 `*` 当续行），第三轮出在新的边规则与旧的 ±1 容差的交互里；每次都是真问题，修完又冒新实例。所以拆成两个变更：本变更只含结构性的、占 869/919 的部分，`validator-multiline-calls` 含文字启发式最重的部分，各自有独立的评审轮次。

AI-first scope gate：这是机器校验器本身的判定规则，要确定性复用，没有 skill / prompt 的替代；改的是校验器宽严，不是新增抽取。

## Goals / Non-Goals

**Goals:**
- 上表五类在真实冒烟图上归零（折行声明头的 4 个方法及其 16 条边除外，那归 `validator-multiline-calls`），且归零不靠放宽到错位也能通过。
- 校验器仍然看得见已知假样本（错位锚点、指向别处的证据行、两边同时偏一行的节点与边），宽容只给抽取器写的证据。
- 过长的前导行可见：既不静默放过也不误报。

**Non-Goals:**
- 不改抽取器、不改 `lineRange` 与证据行的定义；不改 `EXCAVATOR_MAX_CONTRADICTED` 与 `deploy/`。
- 不处理 `calls` 与折行声明头，不引入语言解析器或按语言分支。

## Decisions

**D1　改验证器，不改抽取器。** tree-sitter 的范围包含注解是该语言的真实声明边界，证据行取成员范围起点也是一致的约定。把抽取器改成指向名字行会动事实摘要、快照、`source-index` 与全部下游测试，而且抽取器写的是对的。验证器才是过严的一侧。备选「让抽取器同时写名字行」被否决：多一个字段，所有消费者要同步，收益只是验证器少一点文本规则。

**D2　锚点：按结构跳前导行，不放宽固定窗口。** 距离最远 22 行，若把 ±1 改成 ±25，一个错位 20 行、落进别的声明里的锚点会被确认，验证器就看不见错位了。改成：从 `lineRange[0]` 向前，越过空行、注释、注解 / 装饰器 / 属性（含参数跨行）；停在第一行不是这些的行，名字必须在这一行。落在方法体或别的声明里的错位不是前导行，跳不过去，所以仍被报出。原有的起点 ±1 判定保留，所以新规则是原规则的并集。

前导行的文本规则（语言无关，不做解析）：
- 空行；`//`、`#`（后跟空白或结尾）开头的行，以及 `*` 后跟空白、`/` 或结尾的行（块注释的续行）；`/* … */` 块（含块内各行）。`*p = 1;` 之类以 `*` 开头的语句不是注释续行。
- 以 `@`（Java / Kotlin / TS / Python / Swift）、`#[`（Rust）开头的注解行，或形如 `[Name(` / `[Name]` / `[Name,` 的属性行（C#）；括号 `(`、`[`、`{` 按配平计，字符串字面量内的括号不计，直到配平后才算这条注解结束，所以多行参数块整体被越过。`@interface`（声明一个类型）与 `@name = value`、`@@name += value`（给实例变量或类变量赋值）不是注解。括号属性在配平之后必须以 `]` 结束，否则它是数组字面量的一行（`[make(1), 2],`），构造从它开始的那一行起。
- 注解之后同一行还有声明（`@Override public void f()`）的情形由原有的起点 ±1 判定承接。

**D3　边：读图，不读文字。** `contains` / `exports` / `implements` / `overrides` 的证据行是某个端点节点范围的第一行（注解），名字在跳过注解之后的声明行上。对这些边的证据行用文字规则（跳前导行、跟折行的声明头）是可行的，但宽容由「这一行读起来像什么」决定，可以套在任何被引用的行上，于是每种语言的每种语句写法都可能撞上，逐个补就补不完。

改为数据规则：不带 `token` 的抽取器证据，当被引用的行恰是某个端点节点自己 `lineRange[0]`、该节点的名字是期望的 token、且它自己的锚点已被**精确**确认时，边被确认。这是图里的事实，与那一行文字的样子无关：引用任何别的行（别的成员的注解、方法体里的行、语句）都不享受这条。

「精确」是为了不让容差传递：节点自己的锚点检查保持 ±1（改它会动既有行为），但一个靠 ±1 才通过的锚点，不应再替引用它范围起点的边担保；否则范围与证据行同时偏一行，边就被确认了，而这样的边在改动之前是矛盾的。实现上，锚点被放进可信集合当且仅当名字就在 `lineRange[0]` 那一行，或在跳过前导行之后的那一行。判据是这两个位置，**不是**「命中位置等于起点」：`@Override` 在 179 行、声明在 180 行时，名字既在跳过前导行之后的那一行，也落在 ±1 窗口内，这是 822 条真边的常态，必须可信；只有名字既不在起点、也不在跳过之后那一行、只在 ±1 窗口里时，才不可信（范围比声明早一行或晚一行，且那一行不是前导行）。

它还带来一个一致性：一个锚点已经错了的节点，不再能替引用它范围起点的边担保（在植入错位锚点的副本里，因此多出的矛盾全部触及一个被植入错位的节点）。

带 `token` 的条目（`mentions`、`references`、`injects`、`routes`、JSX 标签、到端点的 `contains`）已经写明「这一行写着什么」，引用错行就是矛盾，不享受任何新宽容（既有的 `injects` / `references` 用例在放宽时当场变红，才发现这点）。`calls` 不走这条，核对不变。模型引用的证据（`source: "model"`）是不可信输入，只核对被引用的那一行，所以新宽容不可能被模型构造出来的内容触发。

**D4　上限是一个可见的桶，不是悄悄放过。** 前导行超过扫描上限（常量 `CONSTRUCT_SCAN_LINES = 400`）仍没有结束时，节点标 `unverified`，计入新缺口 `construct-too-long`，既不确认也不算 contradicted；没有「不知道算过」的第四态。上限只对锚点可达，边不扫描。400 来自：真实冒烟里最长的合法前导块是 22 行，留一个数量级的余量，同时把单个锚点的最坏扫描成本压在常数内。

**D5　改动的数据流。** 抽出一个纯函数 `skipLeadingLines(reader, file, line)`，返回「行号 / 过长 / 无」三态，锚点检查调用它；锚点检查多维护一个「精确确认」的节点集合，边检查读它。`validateAgainstSource` 的结构不变，报告多一个计数 `constructTooLong`（0 时不出缺口，与现有计数同口径），CLI 汇总行多一个字段。SKILL.md 的 Phase 6b 检查说明改一处散文。

## Risks / Trade-offs

- **[前导行的文字规则把一行语句当成前导行，下一行又含名字，锚点被错误确认]** → 这是本变更仅剩的文字启发式。整类用一张语句形状表测试（`import os`、`export default router`、`@count = 0`、`*p = 1;`、数组行等，每行写两遍再接声明：规则若把它当前导行，就会一路跳到声明而被确认，从而被测出；只写一遍时，错误地跳过它也会在下一行停住，测不出来）；用变异检查这张表会咬人。
- **[错位锚点落在纯前导行里（注释、注解）会被确认]** → 这与抽取器对被注解声明给出的范围无法区分，是 D2 的固有边界；错位进方法体或别的声明仍被报出，测试钉死。
- **[边规则让一个锚点已错的节点牵连它的边]** → 这是预期的一致性，不是误报；验收记录里单独统计这类牵连，要求全部触及被植入错位的节点。
- **[折行声明头的 4 个方法在本变更之后仍被判矛盾]** → 已知，归 `validator-multiline-calls`；验收里逐个列出，不算残余的「机制漏判」。
- **[400 行上限的 `unverified` 被误当作「通过」]** → `unverified` 不进 `anchor-mismatch`，但缺口 `construct-too-long` 带计数与样例；验收记录要写该计数。

## Migration Plan

校验器是纯函数加一个 CLI，输出字段只增不减（`counts.constructTooLong`、缺口 `construct-too-long`、CLI 汇总字段）。旧产物重新验证即可得到新结果，无数据迁移。回滚就是还原 `validate-graph.mjs`；旧阈值与 `deploy/` 未动。
