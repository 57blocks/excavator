## Context

explain 与 diff 的回复由最后一条命令打印：分析先写进数据目录里的固定文件，再 `cat` 它，回复就是它打印的行（explain-reply-language D2、diff-reply-language D2）。这条做法保住了回复的形式，但留下两个缺口：

- 打印的文件不一定是本次写的；
- 打印的内容不一定能完整到达模型。

onboard 的回复只有路径与一句话，没有这两个缺口，本变更只改它的契约测试。

语言规则契约测试的检查器 `languageRuleProblems` 返回问题清单。坏副本只断言清单非空，所以一个检查被删掉后，只要同一个坏副本还触发别的检查，测试照样绿。基线见 proposal。

## Goals / Non-Goals

**Goals:**
- 本次写入没有落地时，回复命令失败，不打印任何文件；
- 同一项目里重叠的两次运行，各自回复自己的分析；
- 回复不会被宿主截断：超过上限的文件不打印，由模型缩短后重跑；
- 8 个语言规则契约测试里的每个检查，删掉后至少一个测试变红。

**Non-Goals:**
- 不改五个标题、Language 段与其它步骤的措辞；
- 不评估命令失败后模型缩短分析的质量；
- 不为其它宿主或调小了 `BASH_MAX_OUTPUT_LENGTH` 的设置单独定上限（见风险）。

## Decisions

### D1 本次运行自己的文件，打印后改名为固定名

explain 第 8 步（diff 第 7 步）开头先运行一条命令，打印本次的文件路径：

```bash
# this run's file for the explanation
echo "$(pwd)/.excavator/explanation-$(date -u +%Y%m%dT%H%M%SZ)-$$.md"
```

模型把解释写到这个路径。回复命令由模型填入同一个路径（skill 的各个 bash 块不共享变量，与 prd、view 的 `"<…>"` 占位做法相同），然后按顺序：
- 文件不存在：说明后以非零退出；
- 超过上限：说明后以非零退出；
- 否则：`cat` 它，再 `mv -f` 成同目录下的 `explanation.md`。

**为什么这样能堵住两个缺口：**
- **写入没有落地。** 本次的文件不存在，命令失败，什么都不打印。路径每次都是新的，写入工具也就不会因为「已存在、没读过」而拒绝。
- **两次运行重叠。** 各自的路径不同，各打印各的。时间精确到秒；同一秒内的两个 shell 进程号不同。
- **路径没填或填错。** `[ -f ]` 不成立，命令失败。

**为什么用绝对路径：** 宿主的写入工具要绝对路径，打印绝对路径就不用模型自己拼。

**为什么打印后改名为固定名：** 每次的文件都留着会在 `.excavator/` 里越积越多。改名后，`.excavator/explanation.md` 仍是最后一次的解释，含义与改前相同。改名放在 `cat` 成功之后，失败时旧的固定文件不动。用 `mv -f`，因为交互配置里的 `mv -i` 别名在没有终端时会拒绝覆盖。

**否决的备选：**
- **写之前先删固定文件。** 堵住了写入没有落地，堵不住两次运行重叠：后写的覆盖先写的，先运行回复命令的那次打印的是别人的分析。
- **用 `mktemp` 先建好文件。** 文件已经存在、本会话没读过，宿主的写入工具会拒绝覆盖——这正是要堵的原因之一。所以这里只打印路径，不建文件。
- **每次的文件留着不改名。** 文件会越积越多，固定名也不再指向最后一次的解释。

### D2 长度上限 25,000 字节，超过就不打印

在 Claude Code 里实测：
- 25,000 字节的输出原样到达；
- 30,591 字节的输出，模型只看到前 2 KB 的预览。

所以：
- 第 8 步写明文件不超过 25,000 字节，并说明为什么；
- 回复命令按 `wc -c` 检查，超过就不打印；
- 模型缩短文件后重跑。

25,000 字节比 30,000 字符的默认上限留出 5,000 字节余量。

**为什么数字节：** `wc -c` 在各平台的结果一致。UTF-8 的字节数不小于字符数，所以字节上限同时也是字符上限。代价是中文的解释最多约 8,300 字。

**否决的备选：**
- **分段打印。** 回复要由几条命令的输出拼起来。命令之间的播报会并进回复，这正是 diff-reply-language D2 改用单条命令打印的原因。
- **只打印放得下的几节，再加上文件路径。** 用户收到的分析缺几节；那行路径提示还要另管它的语言。
- **代价：** 很大的改动或组件，它的分析要压缩到 25,000 字节以内。作为聊天回复，这个长度已经超出一般的阅读量。

### D3 diff 的参数提示

frontmatter 改为 `argument-hint: "[pr-number] [--language <lang>]"`，写法与 explain 的 `[file-path] [--language <lang>]` 相同。第 2 步的措辞不变。

### D4 坏副本断言它针对的问题

每个坏副本写成 `[副本, 问题]`，断言写成 `expect(languageRuleProblems(副本)).toContain(问题)`。

**为什么断言 `toContain` 而不是整张清单相等：**
- 与 `tests/language/chat-request-language.test.mjs` 的写法一致；
- 断言整张清单相等，会把每个副本连带触发的其它检查也钉死。改一个检查，就要跟着改一串与它无关的断言。

**每个检查都有坏副本：** 各测试里每个检查至少是一个坏副本的断言对象。doc-map 原来没有坏副本能触发「Step 7 的 Language 段在建议检查之前」，补一个 `beforeCheck`：把 Step 7 的 Language 段挪到建议检查之前，做法与 hotspots 相同。

**装置怎样验证：** 用一个变异脚本，它放在 scratchpad 里，不进仓库：
- 逐个把检查器里的 `problems.push(` 换成空操作；
- 每次写一份副本到原测试旁边，只跑这份副本，跑完删除；
- 未变异的副本必须全绿。

### D5 explain 与 diff 的契约测试（改动部分）

- **第 8 步（diff 第 7 步）：** 开头句、打印路径的命令、25,000 字节那句、五个标题的顺序。
- **打印路径的命令：** 在临时项目里实际运行，打印的是项目里 `.excavator/explanation-<UTC 时间>-<进程号>.md` 形式的绝对路径。另外把 `date` 换成总是打印同一时刻的假命令，再运行两次，两次的路径必须不同。
- **回复命令：** 在临时项目里把路径填进去，实际运行，覆盖下面几种情况：
  - **本次的文件在：** 逐字打印，退出码 0；之后固定名的文件与它相同，本次的文件已不在；
  - **本次的文件不在，固定名是上一次的：** 退出码非 0，stdout 为空，stderr 说本次的文件不存在，固定名的文件不变；
  - **两次运行各有自己的文件：** 各打印各的；
  - **25,000 字节：** 照样打印；
  - **25,001 字节：** 退出码非 0，stdout 为空，stderr 说超长，文件留在原处。
- **第 9 步（diff 第 8 步）：** 失败时怎么做那句在，skill 仍以「回复只能是它打印的内容」结尾。
- **diff 的 `argument-hint`。**

## Risks / Trade-offs

- **截断上限按 Claude Code 的默认值定。** 用户把 `BASH_MAX_OUTPUT_LENGTH` 调到 25,000 以下，或者别的宿主上限更低时，仍可能截断。
- **路径由模型抄写。** 抄错时命令失败，不会打印错的文件。没有真实运行核对模型能否一次抄对，代价是可能多一轮重试。
- **中断的运行会留下文件。** 运行在回复之前中断，本次的文件留在 `.excavator/` 里，不会被下一次运行用到。
- **分析受长度上限约束。** 超长时由模型缩短，缩短的质量没有确定性的核对。
