## Why

`excavator-product-handbook` 现在有约 1.48 万行脚本、165 个模块和约 40 条命令。大部分代码用来守格式：每一部分写成固定键的 JSON（事实表、发现、概览、架构、排序、对策、主题、领域、目录、流程图），由各自的检查器核对；页面再从这些 JSON 拼出来。

一次纯 skill 的对照试验说明，内容质量靠的不是这些格式：
- **试验做法：** 在一个私有语料（68 个功能）上取 5 个功能，从小到最大，覆盖公开、家长、教师、设置、自动运行。一份散文提示词写一章 Markdown，每句带 `路径:行` 出处，不写事实表，不跑检查脚本。拿它和上一次全量运行（现有 skill）的同一章做盲审对比。
- **准确度：** 各抽 75 句，纯 skill 74 句成立、1 句部分成立、0 句错；现有 skill 71 句成立、4 句部分成立、0 句错。
- **覆盖：** 只在一版里出现的事实，纯 skill 105 条，其中核对属实 86、错 1；现有 skill 57 条，其中属实 51、错 1。
- **发现：** 纯 skill 27 条，现有 skill 20 条，全部是真缺陷。
- **花费：** 写作花费相近，$12.0 对约 $13.6。

纯 skill 版的缺点是格式：1 处引文行号超出文件，13 处引文超过 80 行，34 行事实没带引文。这些用一个很小的收尾检查就能挡住。

上一次全量运行约八成的花费在功能写作上。省下 JSON 事实表和逐部分的检查器之后，写作者能把精力放在内容上，维护也简单得多。

## What Changes

- **BREAKING**：模型写的每一部分都改成一章 Markdown，由写作子代理按散文提示词写，包括系统概览与架构、功能章节、业务领域与流程、角色与权限、通知与定时任务、横切主题、发现与级别、对策。不再写任何 JSON 事实表、发现文件、概览文件、排序与对策与主题文件、领域文件或流程图文件，也不再有逐部分的检查命令（`check-entry`、`check-findings`、`check-overview`、`check-priority`、`check-remedies`、`check-topics`、`check-domains`、`check-domain-flows`、`check-outline`、`check-architecture` 及对应的 `try-*`）。
- 每章用同一套 Markdown 约定：
  - 事实句以引文组结尾；
  - 「待确认」与「问题」两节的标题取固定文字表里的文字；
  - 可以画 mermaid 图。
- **一条收尾检查命令 `check`，取代全部逐部分检查。** 它逐章检查：
  - 引文的文件在项目里，行号在范围内，每条不超过 80 行；
  - 事实行带引文；
  - 读者文字里没有代码形状的词；
  - 对策以外不出现建议词。

  不通过的章重派一次，仍不通过就保留原文，并在手册里写明没有通过。它也替代阶段门：功能章没写完时，拒绝开始跨功能章节。
- **跨功能的章节读功能章节，不读代码。** 它们照抄所依据那一行的引文组。领域、角色、通知、主题、缺陷、对策，各由一个子代理写一章。原来按领域与按发现分的 39 条主题通道合并掉。
- **只保留四类脚本：**
  - 入口候选与地图守恒（`candidates`、`applications`、`check-map`）；
  - 结构化事实，即数据、状态字典与代码健康（`data`、`history`）；
  - 收尾检查（`check`）；
  - 拼装与页面（`assemble`、`page`、`reply`）。

  另外还有固定文字表的核对 `check-ui`。删除其余命令，以及它们独占的库模块与测试。
- **BREAKING：** `handbook.md` 与页面都从同一批 Markdown 生成。产品视图去掉引文，技术视图把引文显示成文件与行。页面改为渲染 Markdown 与 mermaid，做法与 `prd-report-page` 相同；导航按目录分组，保留两种视图的切换。原来由 JSON 算出的实体页、矩阵、流程图组件不再存在，相应内容在跨功能章节里由模型写。
- **每章写成便于扫读的版式**：
  - 段落不超过 4 句；
  - 功能章节有固定节序；
  - 并列内容用列表，多属性条目用表格；
  - 多步操作画流程图，多状态记录画状态图。

  `check` 会核对其中能确定判定的部分。
- **沿用 `--features`、`--sections`、`--language`（默认英文）与 `--fresh`。** 只写部分功能时，跨功能各章等全部功能写完再写。之后不带 `--features` 再跑一次，只补缺的章。
- **续跑以文件为准。** 一章文件存在并通过 `check` 就算完成。`state.json` 只记每章的检查结果与尝试次数，换用新的格式串。
- 不论本次运行花了多少，编排者都为每个功能派发写作。功能章没写完时，`check` 拒绝跨功能阶段并列出缺的功能。这条约束保留下来。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `product-handbook`：
  - **删去：** 结构化条目、逐项核对、追查、事实表与发现文件的形状、各部分的检查器、由实体算出的页面。
  - **改为：** 散文写作的章节、一条收尾检查、跨功能章节读章节、从 Markdown 拼装与渲染页面、以文件为准的续跑。
  - **保留：** 入口候选与守恒、地图、只读源码、语言、数据部分、状态字典、代码健康。
  - **修改：** 子代理的工具只剩写作代理。

## Impact

- **`skills/excavator-product-handbook/`：**
  - `SKILL.md`、`stages/`、`sections/` 重写；
  - `handbook.mjs` 的命令表缩到 12 条（见 design D1）；
  - `lib/` 删去事实表、发现、概览、架构、排序、对策、主题、领域、目录、流程图、实体、条目解析与渲染相关的模块；保留候选、应用根、地图、数据、字典、历史、固定文字、引文定位与读者文字检查；
  - 测试同步删减与新增。
- **`packages/product-handbook-page/`：** 页面数据改为「目录 + 每章 Markdown + 脚本算出的数据、字典与代码健康」；页面组件改为渲染 Markdown 与 mermaid，并加入 `react-markdown`、`remark-gfm`、`mermaid` 依赖（与 `prd-report-page` 同版本）；删去由实体 JSON 渲染的组件。
- **`agents/excavator-handbook-writer.md`：** 描述改为写一章 Markdown，工具不变。
- **测试：** 部署夹具与插件加载测试里与手册相关的部分。
- **输出目录：** 旧运行的输出目录不能续跑，要用 `--fresh`。按格式串判断：新的 `state.json` 用新格式串，旧格式串的目录续跑时提示用 `--fresh`。
