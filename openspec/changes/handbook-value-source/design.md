## Context

动机见 proposal.md。相关现状（均在 `product-handbook-map` 的 D14）：

- 追查者（`excavator-handbook-tracer`，Sonnet）每份至多 25 项，只给主张与引文的文件和行号，自己读全项目，每项判 `holds` 或 `contradicted`；`contradicted` 的项由 `trace-verdicts` 删去。
- 追查者定义里写着「只是少说了什么的主张成立」，「说得比代码宽」才是矛盾，要检验的词是「所有」「每个」「总是」、角色、顺序、位置、数量。没有一条讲「来源」。
- 上一变更的方差试验：同一份追查文件再派两名追查者、同一模型，前一处值来源错误 3 次都判 `holds`，理由里写的是「注意到了上限，属于少说」；后一处没有一次指出日期来源。

## Goals / Non-Goals

**Goals**
- 主张说错一个值从哪里来时，追查者判 `contradicted`。
- 不多删真话：已被独立抽查确认为真的项不因新规则被判矛盾。
- 原来抓得住的（插入位置、「三步总在」）不回归。

**Non-Goals**
- 不改脚本、状态与核对者；不改召回（种子文件之外的「未知」仍是召回问题）。

## Decisions

### D1 规则写进追查者，不另开一轮（方向 a，否决方向 b）

两个方向先在同一个装置（O1）上比，再定实现：

- **(a) 追查者规则**：在现有追查者定义里加「追值的来源」一步和「说错来源不是少说」一条判法。
- **(b) 专门一轮**：另一个 agent 只看说了来源的主张，把数据追回到读取它的地方，其余项直接判 `holds`；脚本要为每份多派一名、多一份判词文件并合并。

第一轮装置上，两者抓到的值来源错误相同（津贴、植入的同类错误），漏的也相同（汇率日期：两者都按「每个处理函数看一处换算」读，没看到差旅明细里按整段出差日期换算的那两处），已知为真的项都没有误判。(a) 同时保留了追查者原来的职责，抓到了插入位置、「三步总在」，还多抓到一处真错（同地往返的判定比主张窄）；(b) 按设计不看这些。所以 (b) 只多花一轮子代理（每个功能约多一次追查的花费）和一个 agent、一份脚本状态，没多抓到任何东西。按 AGENTS.md 的 AI-first 门，能由提示词完成的不写代码，取 (a)。

第一轮的共同漏判，在 (a) 上加一句补上（D2 第二点），再做两次重复（O1）。重复暴露了两种误判，又各补一句（D2 第三点与判法里「查找细节不是另一个来源」），才过了 O1；过程见验收记录。

### D2 规则的内容

写进追查者定义「The job」一节，作为独立的一步：

1. 主张说一个值从哪里来（取自、算自、按哪个日期、限定在哪个范围；例如「按客户资料」「按用户填写」「按发货那天的汇率」「本月的」「所有明细的」「服务端按 X 重新算」）时，找到算出这个值的那一行，把计算的每个输入追回到读取它的那一行：提交的请求字段、查询载入的记录的列与那条查询、常量、配置值。有几种实现就追几种。
2. 主张对一整类值说来源（每笔换算、每个日期、每个总额）时，在这个功能的路径上搜出计算这类值的函数（换算、查找、汇率）的每一次调用，逐个看它的输入：同一个处理函数里可以有几处同类计算、来源各不相同，每个处理函数只看一处不够。第一轮的共同漏判就是这样来的。
3. 比对主张的每一部分时，主张用的是产品自己定义并显示的值（一条明细的金额、小计、余额），就拿产品的定义比：找到填这个值的代码。只有代码用的不是这个值才算矛盾，「换我会这样算」不算。第二轮里一名追查者把「总额是各明细折合人民币金额之和」判成矛盾：它拿总额去比发票的折合金额，而产品对差旅明细金额的定义本来就含封顶，总额加的正是它。

判法一节在「只是少说了什么的主张成立」之后加一条：说错来源不是少说。主张说值取自、算自、按日期或限定于 X，而代码从 Y（别的字段、记录、日期、列表或范围）取，判 `contradicted`；即使 X 在旁边起别的作用（只决定有没有这个值、由同一个函数载入、通常与 Y 相等），也即使主张只对其中一种明细说错。同一条里写明：来源是代码读的那个输入；按这个输入查值的细节（当天没有就取更早最近的一条、舍入、找不到时的默认值）不是另一个来源。第二轮里两项为真的对照被一名追查者判成矛盾，理由正是「周末退到前一个工作日的汇率」。

输出一节：说了来源的主张判 `holds` 时，理由写明每个输入在哪一行读取。这让「没追」在理由里看得出来；脚本不检查这一点（判断主张是否说了来源是语义题，脚本做不了）。

**例子要中性。** 规则里的例子不照搬已知的错误：装置里的错误正是要测的东西，例子与它同形会让装置量出虚高的捕获率。判法的例子是「文档的审阅人说是团队成员，代码从项目设置里的审阅人列表读取，团队只用来判断要不要审阅」；触发词的例子用「按客户资料」「按发货那天的汇率」，查找细节的例子用「当天没有就取更早最近的一条」，都不用装置里的原话（「按交易日期的汇率」「退到前一个工作日」）。第三轮之后才换掉后两处原话，所以装置在写进 agent 文件的原文上再跑一遍（第四轮）。上一轮的变更同样在测试前把照搬已知错误的例子换掉了。

### D3 代价

- 精度：新规则把「少说」与「说错来源」分开，可能把一些真话判成来源不对（例如主张说「按日期」而代码在周末退到前一个工作日）。O1 量已知为真的项；规则只在代码「从别处取值」时判矛盾，取值规则的细节（退到前一个工作日）不算换了来源。这一点必须写进规则原文：第二轮它只写在本设计里、没写进规则，两项对照就被判成了矛盾。
- 花费：追查者对说了来源的主张要多追几跳。O2 记录。

## Risks / Trade-offs

- [R1 装置太小：三份、约 70 项，已知错误 5 处] → 每个方向每份跑两次看方差；O2 的真实运行与独立抽查是最终判据。
- [R2 规则对一整类值逐个查调用，在大功能上读得更多] → 每份仍至多 25 项；O2 记录花费与时长。
- [R3 同一模型的盲点] → O2 的抽查由 Opus 做，与 Sonnet 追查者独立。

## Acceptance oracles（动手实现前写死）

- **O1 装置**（仓库外的副本，不跑真实运行）：上一轮真实运行的追查文件第 2、3、4 份（25、25、14 项）的副本；第 4 份末尾植入 3 项：一项更早一次运行里两名核对者删掉的同类错误（津贴「按所选申请的行程重新算」），两项同类真话作对照（「其他」明细按它自己填写的日期取汇率；加班明细按所关联加班申请上的日期取汇率），都经我对照源码确认。
  - 已知错误：值来源 3 处（津贴、汇率日期、植入项），其他 2 处（插入位置、「三步总在」）。
  - 已知为真：此前两次独立抽查判为 `verified` 的项（含曾被审读者误判、后经源码纠正为真的总额一项）与两项对照。
  - 通过条件：选定的方向在每份上跑两次，3 处值来源错误在两次里都判 `contradicted`；插入位置与「三步总在」两次都不回归；任一次都没有已知为真的项被判 `contradicted`。其余被判 `contradicted` 的项逐条对照源码，记为真错或误判。
- **O2 真实运行**（go-multirepo，「报销」）：在上一轮真实运行的产物副本上把该功能退回 `confirmed`（核对者阶段不变），重装插件，只跑追查（Sonnet 钉死模型、`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`、`--out` 在语料外）。然后由 Opus 审读者按条目项类型分层新抽 30 项（新种子），可读语料全部源码（`.excavator` 除外），对照源码判定。主张的矛盾数为 0 即达标；未达标照实记录，不挪判据。能从种子以外文件回答的「未知」照旧记为召回问题。记录花费、时长、删去的项及每项真假。
- **O3 门**：受影响的测试（追查者合约测试所在文件）、`node scripts/check-refs.mjs`、`openspec validate --all --strict` 在本地；全量三件套在分离检出里跑。

## 验收记录

**O1 装置**（Sonnet，每次一名追查者读一份；判定按仓库外的真值表；已知错误：值来源 3 处 S1 津贴、S2 汇率日期、S3 植入项，其他 2 处 X1 插入位置、X2「三步总在」；已知为真 30 项，含总额一项与两项对照）：

- 第 4 轮满足 O1 的通过条件。第 0 轮的 X1、X2 取自上一变更真实运行里的那一次追查。
- S2 的真因：第 1 轮两种方向都把「每个处理函数看一处换算」当成看全了，没看到差旅明细里津贴与发票按整段出差日期取汇率的两处；加班明细取所关联加班申请上的日期，而表单上的日期本来就从那张申请带过来，这一处不算错。第 2 轮起追查者给出的理由都指向差旅那两处。
- 规则之外多抓到的：同地往返的判定比主张窄（每段都是同地往返、但各段地点不同时仍有津贴），第 1 轮 (a) 首次指出、我对照源码确认是真错，之后 (a) 系列 7 次里 6 次抓到；「打开不属于自己的记录会跳到审批详情」，服务端对没有查看权限的人直接拒绝、不会跳转，我对照源码确认是说宽了，第 2–4 轮 6 次里 3 次抓到。两项都不在 O1 的通过条件里。
- 方向 (b) 在第 1 轮之后放弃，理由见 D1。
- 装置里有一名追查者在系统临时目录写过临时脚本又删掉；agent 定义本来就要求只写判词文件，装置的派发语句从第 4 轮起也写明。
