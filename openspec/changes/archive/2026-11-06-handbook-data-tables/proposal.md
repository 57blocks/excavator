## Why

系统手册要有一个「数据」部分，回答重构前最先要理清的问题：系统有哪些表，表结构由哪些迁移脚本建出来，每张表被哪些应用用到，哪些表在代码里找不到名字。

这些都是结构化的代码事实，必须用脚本确定性地抽取，不让模型转写。现有的抽取覆盖不到：
- core 的 SQL 解析只读 `.sql` 文件里的 `CREATE TABLE`；
- 没有迁移记录；
- 没有「文件引用了哪张表」的事实。

常见项目把表结构写在别处：
- ORM 迁移脚本里的建表调用，或其中的 SQL 字符串；
- 模型上声明的表名，如 Go 的 `TableName()` 与 Sequelize 的 `tableName`。

## What Changes

- 手册新增第三个部分 `data`。它不依赖地图，`--sections data` 只跑这一部分。
- 新命令 `handbook.mjs data`：脚本扫描项目，把以下内容写进 `$OUT/data.json`：
  - 表清单：迁移按文件名顺序重放后留下的表，加上模型与 `.sql` 文件声明的表。每张表带声明它的位置（文件:行）。
  - 迁移脚本：每个应用有几个；每张表由哪个迁移建出、最后被哪个迁移改过；被迁移删掉的表单列。
  - 各应用对表的引用：在迁移以外的代码里按表名查找。查找规则固定，见 design。每张表记下出现在哪些应用、哪些文件:行，只记「名字出现在哪里」，不判断读还是写。
  - 可见的缺口：
    - 认不出表名的迁移操作（例如表名来自变量），记文件:行；
    - 拆不出 `up` 与 `down` 的迁移文件；
    - 解析不到字面值的模型表名。
    每个输入都落进一个有名字的桶，没有静默丢弃。
- 拼装：输出目录里有 `data.json` 时，技术视图的手册加「数据」一章，页面加「数据」页：
  - 计数行；
  - 表清单（表名、声明来源、用到它的应用、建表迁移、最后一次改动它的迁移）；
  - 被迁移删掉的表、只有模型声明而没有迁移建出的表、名字只出现在迁移里的表；
  - 缺口清单。
  固定文字都走 `ui.json` 的新键。
- 数据部分不派发子代理，也不需要模型写任何内容。

**不做**：
- 状态字典（枚举值与含义）：下一个变更做；
- 列清单、外键；
- 读写区分；
- 按业务领域分组；
- 产品视图的数据章：表名是技术内容，只放技术视图；
- 改 core 的 SQL 解析或事实图。
