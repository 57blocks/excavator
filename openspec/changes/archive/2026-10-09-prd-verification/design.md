## Context

`excavator-prd` 的 Fineract「贷款账户」PRD（9,857 行，21 分钟，约 62 美元，14 个研究子代理）经独立核对：60 条抽样 56 属实、3 矛盾、1 错归属；39 处「待确认」10 诚实、26 过度保守、3 暂定说法错误；另有多处「待确认」与本文其它章节的明确说法互相矛盾。全部错误落在五类陈述上：否定性结论、可达性/顺序、触发机制、绝对化/不变性、未决项。引用的文件与标识符全部真实存在——问题不在「编出了不存在的东西」，而在「对真实代码下错了结论」。

## Goals / Non-Goals

**Goals**
- 交付前拦下上述五类陈述中的错误，并消解可由代码定论的「待确认」。
- 核对可单独调用，能直接拿既有 PRD 测量准确率、时间、费用。
- 核对的增量时间与费用显著低于独立串行核对（约 37 分钟）。

**Non-Goals**
- 不核对全部陈述；数值、字段、配置等结构化事实不在本变更范围（实测这类说法 0 错误）。
- 不新增确定性脚本；文件/标识符是否存在的审计不纳入本变更。
- 不改变覆盖、图、枚举、术语四项既有自检。

## Decisions

### D1 核对是独立 skill，PRD 调用它

`excavator-verify` 独立成 skill，输入「文档 + 项目根」。理由：(1) 可直接对既有 PRD 测量，验收不必重跑 62 美元的生成；(2) 其它 As-Is 文档（onboard、explain）未来可复用同一核对；(3) PRD skill 只需在 Phase 4 跟随它的流程。代价：多一个 skill 入口与一处跨 skill 引用（经 `$PLUGIN_ROOT/skills/excavator-verify/SKILL.md`，受 check-refs 门约束）。

### D2 只核五类高风险陈述

候选 = 否定性结论 / 可达性与顺序 / 触发机制 / 绝对化与不变性 / 未决项（「待确认」等）。依据是实测错误分布：60 条抽样中数值、默认值、字段类说法全部属实，错误全部集中在这五类。标记词只是起点，候选由模型按语义判定。代价：类别外的错误（例如单纯写错的数字）不在保证范围内——验收里以一条类别外植入样本如实测量并报告，不计入硬门。

### D3 否定性结论必须全仓搜索

「不会发生 / 未被使用 / 不存在」只有在搜遍全仓（全部模块、监听器与事件注册、调度/批处理注册、SQL 与迁移脚本、配置文件）后仍无反例才可判属实。实测的 3 处「待确认」错误全部是只看了局部代码的否定性推测。

### D4 按章节并行，核对者拿到章节原文与候选清单

每个顶层章节（或若干小章节合并）派一个子代理，输入该章行号范围、候选清单与五类核对规则，返回逐条判定、证据与改正句。主代理不重复子代理的源码定位。理由：独立核对慢在单代理串行；PRD 生成本身已证明 14 路并行可行。

### D5 跨章节一致性单独一步

收集全部候选的主题，在全文中搜索同一主题的其它表述；表述冲突时以源码定论，并在 `--fix` 时统一。实测有 4 处「待确认」与本文其它章节的明确说法冲突。

### D6 无第四态

每个候选必须落入判定桶：说法类 verified / contradicted / misattributed / unverifiable；未决项类 resolved-right / resolved-wrong / still-open——把「暂定说法是否正确」并入判定本身，使 resolved-wrong 与 contradicted 一起计入错误。子代理漏回的候选计为 not-checked 并在报告中计数，不得静默消失。

### D7 `--fix` 只改错、不扩写

改正限于：替换错误陈述、把可定论的未决项改写为定论、统一冲突表述、补对应证据到 `<details>`。不新增流程、不给建议（As-Is 纪律），文末追加一段核对摘要（计数 + 基线）。

### D8 写作阶段先行自证（shift-left）

`excavator-prd` 的研究与写作在下五类结论时，须已做全仓搜索并把搜索范围作为证据交回；做不到则写成「待确认」并注明已搜范围。这样事后核对多数是复查已有证据，降低核对成本。

## 验收（动手前写死）

语料：Fineract 测试副本（commit f9c2fcdc，已删除全部文档）与既有贷款账户 PRD 的副本；真实项目输出不提交，仅记录数字。

**A. 装置自检（硬门）**：在 PRD 副本中植入 4 条类别内假陈述，核对必须 4/4 判为 contradicted 或 misattributed：
- P1 绝对化：把「仅当还款期包含 2 月 29 日时年天数取 366，否则 365」改为「无论是否包含 2 月 29 日一律取 366」；
- P2 否定性：把「Charge-off 前先摊销到 Business Date 并记账」改为「不做任何摊销，也不产生会计分录」；
- P3 触发机制：把「短信与邮件活动监听 Loan 已审批、已拒绝、Repayment」改为「不监听任何 Loan 事件，由每日定时任务批量扫描后发送」；
- P4 顺序：把「先权限校验、后任务互斥检查」改为「先互斥检查、后权限校验」。
另植入 1 条类别外样本 P5（Delinquency 分类任务 22:00 改为 23:00），只报告是否被发现，不计入硬门。

**B. 真实错误召回（硬门 ≥ 6/7）**：独立核对确认的 7 处错误——第 3851 行（EMI 期利率口径）、4966 行（Re-age 规则不可达）、8491 行（暂停期重叠判定）、9420 行（Delinquency 重算触发方式）、4205 行（按原 Schedule 计算的开关未被使用）、5309 行（Reschedule 间接触发 Delinquency 重算）、9050 行（修改申请时空账号可清空）。

**C. 精确度（目标 ≥ 80%）**：A/B 以外判为 contradicted/misattributed 的条目逐条人工复核，报告真错比例。

**D. 未决项消解（报告）**：39 处「待确认」中被定论的数量，与独立核对的 26 处过度保守比较。

**E. 一致性（报告）**：已知 4 组章节间冲突（9050↔607、4205↔7224、896/1215↔8602、5383↔6745）中被发现的数量。

**F. 时间与费用（目标）**：单独核对贷款账户 PRD 的墙钟时间 ≤ 生成时间的 50%（≤ 约 10.5 分钟）、费用 ≤ 50%（≤ 约 31 美元）；超出则如实报告并说明原因。

**G. 集成（报告）**：修改后的 `excavator-prd` 在 `fineract-progressive-loan` 范围重跑，与改前（约 12 分钟、13.68 美元）比较时间与费用增量，并报告 `--fix` 改正条数。

## Risks / Trade-offs

- 核对子代理本身也可能误判（把对的改错）→ 验收 C 人工复核；`--fix` 每处改正必须带证据，便于审阅。
- 并行子代理增加并发费用；以验收 F 的实测为准，必要时合并小章节。
- 类别外错误不保证拦截 → 在报告中如实声明核对范围。
- 实测（tasks 6.3/6.4）核对的时间与费用与生成本身相当，未达 F 目标。五类陈述都出现过错误，删减类别会直接漏错；零编造是硬指标，故接受该成本，并以缩小 PRD 范围作为主要降本手段。Sonnet 在探针上更贵且未完成，核对保持 Opus。
