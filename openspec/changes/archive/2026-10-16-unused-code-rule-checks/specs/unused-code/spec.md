## MODIFIED Requirements

### Requirement: 入口判断由宿主 skill 承担

哪些簇入口是程序入口 SHALL 由宿主 skill `excavator-unused-code` 判断（模型），不由脚本判断：框架回调、定时任务、消息监听、`main`、对外 API、序列化与反射约定、测试方法。

skill SHALL：
- 按特征分组决定，并参照已检测框架的附录；
- 把决定写成文件，每条带种类（`entry` 生产入口 / `test-entry` 测试入口）、理由、选出它的查询与节点 id；
- 种类按代码所在位置定：测试代码里的方法，即使由生产机制调用（实现生产接口的测试替身、测试运行器加载的扩展），也是 `test-entry`。测试代码指测试源码目录，以及只被测试依赖的模块；构建发布给其它项目的模块（SDK）不算，即使仓库里只有测试依赖它；
- 程序启动（语言的启动方法如 `main`，脚本顶层代码调用的函数）每次都判为入口；
- id 由查询产生，MUST NOT 手抄。

skill 的决定脚本 SHALL 在写决定文件前检查：
- 模型先写出测试代码的路径范围。选中范围内节点的 `entry`、选中范围外节点的 `test-entry`，脚本都拒绝；
- 名为 `main`、事实里没有调用者的候选，只要还有一个不在任何决定里，脚本就不写决定文件；
- 记录下的查询自带测试代码范围的定义，单独重跑选出同样的 id。

决定只能把候选节点移出候选，MUST NOT 让节点成为候选。`unused-code.mjs report` SHALL 拒绝以下决定文件：
- id 不在候选集里；
- 同一个 id 出现在两条决定里；
- 候选集与当前事实图的摘要不一致。

#### Scenario: 注解入口按组决定
- **WHEN** 候选入口里有 40 个带 `@Scheduled` 的方法
- **THEN** skill 以一条 `entry` 决定移出它们，理由写明调用者是调度器，查询写明按注解选出

#### Scenario: 决定引用了不存在的节点
- **WHEN** 决定文件里有一个不在候选集里的 id
- **THEN** `report` 以非零状态退出，不写产物

#### Scenario: 一个机制同时选中测试与生产代码
- **WHEN** 一条 `entry` 决定按 `equals` 覆写选出候选，其中有测试源码目录里的测试替身
- **THEN** 决定脚本拒绝这条决定；拆成生产部分的 `entry` 与测试部分的 `test-entry` 后通过

#### Scenario: 只被测试依赖的 SDK
- **WHEN** 一个模块在仓库里只被测试依赖，构建把它发布给其它项目
- **THEN** 它不算测试代码，它的公开成员按对外 API 的规则决定

#### Scenario: 启动方法没有决定
- **WHEN** 一个名为 `main`、事实里没有调用者的候选不在任何决定里
- **THEN** 决定脚本以非零状态退出并列出它，不写决定文件

### Requirement: 产物、新鲜度与查询

`report` SHALL 写 `.excavator/unused-code.json`，内容包括：
- 头部：事实摘要、决定摘要、各状态与各可信度计数、残余假设；按语言的候选数、`calls` 边数与各可信度计数，候选集里的每种语言一行；
- 全部决定，每条带种类、理由、查询与命中数；
- 全部未使用候选，每条带原因、可信度、信号、直接引用者与所属组；
- 全部组，每组带入口与成员；
- `test-only` 节点。

头部 SHALL 写明残余假设：
- 未选中的文件不参与普查；
- 按运行时拼接的名字做的反射看不见；
- 构建时生成而不在仓库里的代码看不见；
- 仓库外的调用者只能体现在可见性上；
- 不写出方法名的使用看不见：视图、模板或 JSON 映射以属性名 `foo` 绑定 `getFoo` / `setFoo`，或其它按约定推出的名字；
- 事实图没能解析的调用没有边，事实图的缺口（`calls-unresolved`、`calls-ambiguous`、`calls-caller-unresolved`、`override-uncertain`）记录其数量；原因只陈述事实里有什么，这样被调用的方法靠名字普查挡在 `high` 之外。

`report` SHALL 拒绝没有按语言 `calls` 计数的候选集，提示重新运行 `candidates`。`calls` 为 0 的语言，skill 的汇报与 chat 的回答 SHALL 说明事实里没有该语言的调用，它的节点被列为未使用不说明没有调用者。

skill 的汇报 SHALL：
- 把 `unreferenced` 说成事实里没有引用，MUST NOT 说成没有调用者；
- 只用产物里的字段解释计数。例如没有 `high` 的原因，取自 `medium` 节点的信号统计；
- 逐条列出产物的残余假设。

`report` SHALL 守恒：候选节点数 = 经决定移出的节点数 + `test-only` 节点数 + 未使用节点数。

`excavator-chat` SHALL 在用户问到未使用代码时读这个产物回答：
- 先比对事实摘要，不一致时说明产物已过期；
- 不把 `medium` 或 `low` 说成确定未使用；
- 产物缺失时告诉用户先运行 `excavator-unused-code`。

本能力的任何部分 MUST NOT 删除或修改项目代码。

#### Scenario: 事实变了
- **WHEN** 产物的事实摘要与当前事实图的摘要不同
- **THEN** chat 回答时说明产物已过期，需要重新运行

#### Scenario: 守恒
- **WHEN** 写产物时三类节点数之和不等于候选节点数
- **THEN** `report` 以非零状态退出，不写产物

#### Scenario: 没有 high 的原因
- **WHEN** 产物里没有 `high` 节点
- **THEN** skill 的汇报按 `medium` 节点的信号统计说明它们为什么不是 `high`，不用产物里没有统计的原因
