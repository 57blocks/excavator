## Context

`searched` 是字符串数组。提示词要求「只写搜索」，`link` 只查它非空。四个真实产物（4 个语料，19 条 `not-found` 功能，92 条搜索记录）里结论有三种出现方式：
- 接在搜索后面：` — …`、` -- …`、末尾的括号；
- 单独成一条：「Confirmed …」「No code implements …」；
- 读文件后的判断：「Read of X — it only …」。

提示词里的禁令放在模型写记录的那一刻，仍然没有挡住。按以往的经验，只有禁令、却给了一个能写任何话的位置，模型会把它觉得有用的解释写进去；能挡住的是让那个位置写不进解释，或由脚本拒绝。

## Goals / Non-Goals

**Goals:** 搜索记录里不再有结论；一条搜索记录的每一部分要么是搜的内容，要么是项目里真实存在的位置；报告与 chat 显示同一种写法。

**Non-Goals:** 不让脚本重跑搜索、不记录命中数；不改 `found` 的证据与复核；不处理复核的 150 行窗口与「见某节」类功能这两处已记录的软残余。

## Decisions

### D1 一条搜索是 `{"pattern", "paths"}`

`pattern` 是搜的词或正则，`paths` 是搜的范围。结构里没有放结论的字段；额外的键（例如 `result`、`note`）一律报出，不给结论另开一个位置。

备选：
- 只改提示词：已经写了禁令，真实运行里多数记录仍带结论，再加措辞不可靠。
- 字符串不变，用正则拒绝结论措辞（「only」「no matches」「—」）：依赖语言与措辞，会误伤本身含这些词的搜索词，模型换个说法就绕过。
- 脚本重跑每条搜索并记录命中的文件数，给模型一个可核对的事实代替结论：要处理 grep 基本正则、扩展正则与 Python 正则的方言差异，代码量大，超出这次需要。以后若需要「搜到几个文件」再单独做。

### D2 `link` 核对每条搜索的形状和路径

每条搜索：
- 是对象，恰好有 `pattern` 与 `paths` 两个键；
- `pattern` 是字符串，去掉首尾空白后非空，且没有换行；
- `paths` 是非空数组，每项是非空字符串：
  - 不是绝对路径，不含 `..` 这一段，解析后不在项目目录外；
  - 不带通配符（`*`、`?`、`[`）时，必须是项目里存在的文件或目录，`.` 是项目目录本身；
  - 带通配符时，第一段通配之前的目录必须存在；通配从第一段起（如 `**/*.java`）时不查。

`searched` 对 `found` 与 `not-found` 都按这条核对；`not-found` 仍至少要一条搜索。

路径的核对挡住两件事：结论写进路径（「src/ (only false positives)」不是存在的路径），以及一条声称搜过一个不存在的目录的记录，那本身就是编造的记录。`pattern` 里的结论脚本挡不住，靠提示词与真实验收（O2）去量。

路径按产物里的不可信输入处理：先判绝对路径与 `..`，再解析并确认在项目目录内，越界的只报出、不去读。

### D3 提示词点名不许写的形状

子代理提示词第 5 条改为：一条搜索就是搜了什么（`pattern`）和在哪里搜（`paths`，相对项目目录，`.` 为整个项目），不写别的。逐项点名不许写的内容：搜到或没搜到什么、搜到的东西为什么对不上、代码库有什么或没有什么；这些既不写进 `pattern`、`paths`，也不单独写成一条。读文件不是搜索，不列。

改错说明（Step 4 第 4 项）加上搜索的报错怎么改：路径不在项目里时，写成真正搜过的目录、文件或通配；写不出真实位置的搜索删掉。仍然 MUST NOT 为了通过而让一条 `not-found` 没有搜索。

### D4 报告与 chat 用同一种写法显示

一条搜索显示成 `<pattern> in <paths 用 ", " 连接>`，多条用 `; ` 连接。报告查询与 chat 查询里的这段表达式逐字相同，契约测试比对。

### D5 零兼容

旧产物里字符串形式的 `searched` 不再通过 `link`。不留兼容分支：这个功能今天才合入，旧产物只在验收用的副本里；重跑 `/excavator-doc-map` 即可。chat 读到旧产物时 `jq` 会报错，属于同一情况。

## Risks / Trade-offs

- 结论仍可能写进 `pattern`，脚本看不见。代价由 O2 量出；若真实运行里出现，下一步再考虑 D1 里「脚本重跑搜索」的方案。
- `paths` 只能写真实位置后，「整个项目，排除测试」这类说明写不进去，只能写 `.`。读者重跑时范围会比原搜索宽，只会多搜到，不会让「没找到」的说法变得更强。
- 通配之前的目录要存在，但通配本身是否匹配到文件不查：匹配为空的搜索仍是一条真实的搜索。
