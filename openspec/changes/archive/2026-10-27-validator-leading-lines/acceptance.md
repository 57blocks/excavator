新测试文件 `test_validate_graph_leading_lines.test.mjs` 先在未改动的验证器（`main` 的代码）上跑：93 个用例里 9 个红、84 个绿。红的是真实形状（注解在前的锚点、注解块、属性列表、过长的前导行、CLI 字段、边按范围起点确认）；绿的是护栏（错位锚点、注解后跟另一个名字的声明、语句形状表、模型引用的证据、证据行指向无关行），`main` 本来就把它们判为矛盾。装置看得见已知假样本。

## 6. 评审第 1 轮之后

reviewer 找到 1 个重要问题（两个实例）：Ruby 里以 `@` 开头的语句（`@log.info(item)`、`@items.each do |item|`）被当成注解，JavaScript 与 Python 的交换语句 `[a, b] = [b, a]` 被当成 C# 属性，于是起点落在别的方法体里的节点，锚点被确认为精确，引用该起点的边被确认；`main` 上这些都是矛盾。两个实例都先复现。

判断：这不是两个个例，是同一类。第一版按一行文字的开头（`@`、`[`）判断「这是注解」，而同样的文字在别的语言里是语句。顺着这一类往外查，又找到两种：注解后面同一行还有一个别的声明（`@Override public void other() {}`），和注释后面同一行还有代码（`/* note */ int x = 1;`、` */ int x = 1;`）。五个用例在评审时的代码上全部误确认。

所以改的是判据，不是实例：一行只有在读掉注释和注解之后不剩别的东西时才算前导行；注解、属性、`#` 注释的语法属于哪种语言，由扩展名决定。

- **先验装置**：新的三张表（各语言的语句与带着别的东西的行、各语言真正的前导行、同一段文字放进没有这种语法的语言）在评审时的代码上 18 个红，其中包括评审点到的全部几个，也包括我自己找到的同类。
- **变异**：18 个变异（每个语言开关打开、括号后面的内容被忽略、块注释后面的内容被忽略、`*/` 不读、星号规则放宽、扫描上限失效、边规则的各条）。第一次有 3 个存活：`#[` 对所有语言生效（补了「没有这种语法的语言」一行）；`@interface` 与 `@x = 1` 的专门排除（去掉后测试照样全过，因为新判据已经覆盖它们，是冗余代码，删除）。重跑后全部被拦住。
- **真实图重跑**：与第一次完全一致。919 到 70，`calls` 50 加折行声明头 20，其他 0；非 lambda 植入 367/367，同时偏一行 107/107，多出的 121 条矛盾全部触及被植入错位的节点。

## 7. 评审第 2 轮之后

reviewer 在注释记号上找到同一类的又一个实例：`//`、块注释和星号开头的行在所有语言里都被当成注释，于是 Python 或 Ruby 里表达式续行的 `* b`（星号展开）、`// b`（整除）被跳过，起点落在表达式中间的节点锚点被确认为精确。上一轮我只把注解与属性按扩展名限定，把注释留成了「通用」。先复现，同类的 Ruby 的 `*` 续行、C 里写成 `* p = 1;` 的解引用语句也复现。

这一轮同样改类：`//` 与块注释按 C 系语言限定，`#` 注释补上 PHP，括号里读到的行注释也按同一张表。并且把星号续行与行首 `*/` 这两条规则整个删掉：它们只为「范围起点落在块注释中间」服务，而抽取器给的范围从第一个注解或修饰符开始，不会从注释中间开始，起点落在注释中间本身就是错的锚点，应报矛盾。少一条文字启发式，比给它加语言限制更稳。

- **变异**：20 个变异（每个语言开关打开、括号里的行注释、块注释后面的内容、被删规则复活、边规则的各条）全部被拦住。一度有 1 个存活（`±1 通过的锚点也算可信`），原因是我替换一个 describe 时多删了紧跟着的 ±1 用例；变异检查抓到了这个删除，用例已恢复。
- **真实图重跑**：与之前完全一致（见下）。
