## Context

现状：
- 仓库唯一的工作流是运行镜像：PR 只有改到部署相关文件时才跑，测试那一步只跑三件套（安装、构建、全仓测试），不跑 core 测试、类型检查、引用检查与 OpenSpec 校验。
- `main` 没有分支保护；仓库公开，Actions 对公开仓库免费。
- 全量门只在 agent 本地（macOS）跑。运行镜像工作流最近一次在 Linux 上跑测试，151 个测试文件里 1 个失败：doc-map 的报错把证据路径截到 80 个字符，只在超过 80 个字符时才加「...」；测试却总是期望「...」。macOS 的临时目录路径超过 80 个字符，Linux 的 `/tmp` 不到，于是只在 Linux 上红。
- 隐私检查至今靠 agent 每次开 PR 前手动做：用两份不在仓库里的名单（私有名字是固定字符串，语料名是一条正则）扫改动的行、提交信息与 PR 正文。已归档的早期验收记录里有一个后来才列入私有名单的公开语料名，所以检查只能扫一个 PR 新带来的文字，不能扫整棵树。

GitHub 的几条机制决定了下面的取舍：
- 必过的检查如果因为路径过滤被跳过，算作通过；
- 手动触发（workflow_dispatch）只在工作流文件已经在默认分支上时可用；
- 从 fork 开的 PR 拿不到 secret；
- PR 的作者不能批准自己的 PR。

## Goals / Non-Goals

**Goals:**
- 每个进 `main` 的改动都走 PR，在 Linux 上过全量门；
- 隐私检查在 CI 里跑，名单不进仓库，名单不可用时失败；
- `main` 受保护，管理员也不能绕过。

**Non-Goals:**
- AI 审查、人工批准、风险分级、讨论必须解决：下一步；
- 合并队列；
- 扫描 `main` 已有的内容；
- 支持 fork PR 拿到 secret（不用 `pull_request_target`）；
- 取代本地按改动范围选检查的表：本地仍按表跑。

## Decisions

### D1 CI 每次跑全部检查，一个 job

job 名 `CI gate`，在 `pull_request`、推到 `main` 与手动触发时跑。步骤与 `AGENTS.md` 验证表的并集一致：
1. `pnpm install --frozen-lockfile`
2. `pnpm -r build`
3. `pnpm run typecheck`
4. `node scripts/check-refs.mjs`
5. `npx --yes @fission-ai/openspec@1.10.0 validate --all --strict`
6. `pnpm --filter @excavator/core test`
7. `pnpm test`

理由：
- 不按路径过滤：被跳过的必过检查算通过，过滤条件就是绕过口；合并需要的也正是并集。
- OpenSpec CLI 用 `npx` 钉版本：本地用的是全局安装的同一版本，它不是仓库依赖；为一次校验加依赖会改 lockfile。

代价：每个 PR 多等几分钟（运行镜像的测试 job 只跑三件套就要 5–6 分钟）。

其他设置：
- 只有 PR 的运行会被同一分支的新运行取消；推到 `main` 的运行不取消；
- 超时 45 分钟；
- 权限只读；
- action 钉提交 SHA，与运行镜像工作流用同一组。

### D2 隐私检查扫哪些文字

范围是 base 到 head 的每个提交。历史是公开的，一行加了又在后面的提交删掉，仍然在仓库里，所以逐个提交读，不只读最终的差异：
- **新增的行**：
  - 非合并提交读补丁；
  - 合并提交读 remerge diff：把两个父提交自动重新合并一遍，与合并提交实际的内容比，差出来的正是合并提交自己写进的行（解决冲突或其他手改）。分支要与 `main` 同步（D7）之后，从 `main` 合并进 PR 分支会是常事。
- **提交信息**；
- **作者与提交者**：名字与邮箱；
- **改动的路径**；
- **PR 的标题、分支名与正文**：分支名会写进 `main` 上合并提交的默认信息。

读法：
- 完整遍历历史（`--full-history`）。带路径过滤时，git 默认会简化历史，净改动为零的旁支整个被跳过。
- 每个文件都按文本读（`--text`），不管 git 或 `-diff` 属性怎么判它是二进制；去掉 NUL 字节，UTF-16 文本才能匹配。
- 不用 combined diff（`--cc`）：对含 NUL 的文件，即使加 `--text`，它也只报 "Binary files differ"。
- 三个以上父提交的合并没有 remerge diff，范围里出现就失败（退出 2），让作者一次合并一个分支。

不扫 `main` 已有的内容。

### D3 两份名单，两种范围

- **私有名字**：固定字符串，不分大小写；`pnpm-lock.yaml` 之外处处禁止。lockfile 里是随机的完整性哈希，短名字会偶然命中。
- **语料名**：每行一条正则，不分大小写；`openspec/`、`docs/` 与根目录 Markdown 之外禁止。验收记录写明在哪个语料上验过是证据。

提交信息、作者与 PR 的标题、分支名、正文两份名单都扫，因为它们不是验收记录。

### D4 失败要关、输出要静

- 名单文件不存在，或去掉空行后为空，退出码 2，写明名单不可用。空行要先去掉：一条空的模式会匹配每一行。
- 正则写错也退出 2。
- 只打印「名单 × 来源」的命中行数，不打印命中的文字；有任何命中就退出 1。

### D5 脚本用 Node，不依赖任何包

`scripts/ci/privacy-scan.mjs`，写法跟 `scripts/check-refs.mjs` 一样：零依赖、不联网。

理由：
- 本地 macOS 与 CI 的 Linux 上正则语义相同（BSD 与 GNU grep 的方言不同）；
- 能用 vitest 测。

输入：base、head、两份名单文件，加上任意几个要扫的文本文件（PR 的标题、分支名与正文）。

工作流里：
- secret 经环境变量写到 `RUNNER_TEMP` 下的文件，不内插进脚本，以防注入；
- PR 的标题、分支名与正文在运行时经 API 读取，不取自事件：
  - 重跑旧的运行，或者推送与编辑先后触发、较早的运行被取消，读到的都是当前的文字；
  - 它们不进环境变量，所以不会出现在日志里列出的环境变量值中；
- base 在运行时取 `origin/<目标分支>` 与 head 的合并基点。

### D6 触发与 fork

`Privacy scan` 在两种情况下跑：
- `pull_request` 的 opened、synchronize、reopened、edited，也就是改了标题或正文也重扫；
- 手动触发：读这个分支上开着的 PR；没有 PR 时只扫分支名。否则对 PR 分支的一次手动运行会在同一个提交上留下一个没扫标题与正文的绿检查。

fork 的 PR 拿不到 secret，检查失败，由维护者在本仓库的分支上重开；目前没有来自 fork 的贡献。不用 `pull_request_target`，理由见 Risks 里「PR 能改扫描器与工作流本身」一条。

### D7 分支保护与 secret

用经典的分支保护 API（`PUT /repos/{owner}/{repo}/branches/main/protection`）：
- 必过检查 `CI gate` 与 `Privacy scan`，`strict`（分支必须与 `main` 同步）；
- 必须走 PR，批准数为 0：批准在下一步；
- `enforce_admins` 为真；
- 禁止强推与删除。

不用合并队列：PR 数量少，`strict` 已经保证合并的是在最新 `main` 上验过的内容。

两个 secret：
- `PRIVACY_NAMES`：私有名单，外加一行金丝雀字符串；
- `PRIVACY_CORPUS`：语料正则，外加一行金丝雀。

金丝雀的字面不进仓库，只用于合并后的探针。今后名单以 secret 为准，加名字时两处一起改。

### D8 其余

- 运行镜像的测试 job 保留：镜像 job 依赖它。只改开头那句注释。
- doc-map 测试按脚本的规则写期望：路径超过 80 个字符才截断并加「...」。

## Oracles（动手前写死）

- **O1 装置**：vitest 在临时 git 仓库上用合成名单测脚本，名单里不放真实名字。逐条覆盖：
  - 每种来源都能检出：新增行、提交信息、路径、标题与正文；
  - 两种范围：语料名在 `openspec/`、`docs/` 与根目录 Markdown 里不计，在 `skills/` 下的 Markdown 与代码里计；私有名字处处计，lockfile 除外；
  - 加了又删的行；合并提交解决冲突时写进的行；
  - 名单缺失、全是空行、正则写错都退出 2；
  - 输出里没有命中的文字；
  - 干净的范围退出 0。

  另做变异：逐个关掉脚本的一种来源，确认有测试变红，做完还原。

  审查后补充（见验收记录）：合并的旁支加了又删的行；合并提交写进、后来又删掉的行；干净合并自己新增的文件（含二进制）；git 判为二进制的文件、`-diff` 属性下的文件与 UTF-16 文本；作者；语料名在路径里；语料名单缺失或为空；三个以上父提交的合并退出 2。
- **O2 全量门**：本地全量门绿；PR 上的 `CI gate` 在 Linux 上绿，包括 doc-map 的修复。修复前在 Linux 上红，已由运行镜像的最近一次运行观察到。
- **O3 在真实环境里失败要关**：设置 secret 之前，这个 PR 的 `Privacy scan` 是红的，日志写明名单不可用；`gh secret set` 之后重跑变绿。
- **O4 合并后的探针**：在临时分支上手动触发：
  - (a) 一个失败的测试，`CI gate` 红；
  - (b) 私有名单的金丝雀写进 `docs/`，`Privacy scan` 红；
  - (c) 语料金丝雀写进 `docs/`，绿；
  - (d) 语料金丝雀写进代码文件，红；
  - (e) 私有名单的金丝雀只在提交信息里，红。

  日志里没有金丝雀的字面。探针分支事后删除。
- **O5 保护**：读回分支保护，与 D7 一致。下一个 PR（归档记录）在检查跑完前 `mergeable_state` 为 `blocked`，变绿后可合并。审查后补充：把这个 PR 的标题改成含私有名单金丝雀，`Privacy scan` 重扫变红；改回后变绿。
- **O6 隐私**：本 PR 的改动行、提交信息、路径与正文，用本地名单做的手动检查全为 0。

## Risks / Trade-offs

- **Linux 上偶发的超时会挡住所有合并**：管理员也不能绕过。重跑即可；真要放开，由用户临时改保护。
- **名单有两份**（agent 本地与 secret）：以 secret 为准，加名字两处一起改。
- **推送即公开**：CI 只拦得住内容进 `main`，拦不住它出现在公开仓库。推送的分支立刻公开；被强推覆盖的提交仍能按 SHA 访问。所以有名单的会话推送前仍要在本地检查。
- **PR 能改扫描器与工作流本身**：`pull_request` 运行的是 PR 自己的版本。改了扫描器的 PR 由改过的扫描器检查；改坏的调试输出会把名单印进公开日志；删掉 `ci.yml` 一步的 PR 照样得到绿的 `CI gate`。
  - 本步不改用 `pull_request_target`。它让检查跑在 `main` 的版本上，但这个 PR 自己验证不了它，它的检查挂在哪个提交上也没验证过。
  - 由下一步的风险分级兜住：改 `.github/`、`scripts/ci/` 的 PR 定为高风险，由用户合并。
- **扫不到的**：
  - LFS 存储里的内容（只读得到指针文本）；
  - 压缩或编码过的内容；
  - 合并时手打的合并信息（本流程用默认信息）。
- **每个 PR 多等几分钟**；`main` 前进后，其他 PR 都要先同步再重跑。
- **fork 的 PR 无法通过**：目前没有这类贡献，见 D6。

## 验收记录（合并前）

- **O1 装置**：`tests/ci/privacy-scan.test.mjs` 最终 18 个测试。
  - 第一版 13 个测试，15 个变异全部让测试变红。
  - 审查后重写，做 22 个变异，都在模拟 Linux 的环境里跑（短 `TMPDIR`，`user.useConfigOnly=true` 即没有 git 身份）。其中 21 个各让至少一个测试变红：
    - 去掉一种来源，或去掉 remerge、换成 combined diff；
    - 去掉 `--text`，保留 NUL 字节；
    - 放宽或收窄范围，保留空行，按前缀跳过头部；
    - 名字或语料区分大小写，空名单放行，打印命中，恒退出 0，放过三个以上父提交的合并。
  - 存活的 1 个只去掉 `--full-history`：读合并差异时，git 本来就遍历全部提交。两者一起去掉时，三个与合并相关的测试变红。保留 `--full-history`，让遍历全部提交不依赖另一个开关的副作用。
- **O2 全量门**：
  - **第一版本地全量门**：绿。core 62 个文件 1437 个测试；全仓 154 个文件，4131 通过、4 跳过。
  - **PR 上第一次 `CI gate`**：红在新测试本身。Linux runner 没有 git 身份，测试里那条 `git merge` 没带身份就退出了；前置断言只查退出码，所以测试带着错误状态往下走。本地用 `user.useConfigOnly=true` 复现：旧测试红、新测试绿。修法是 merge 带上身份，并断言 `MERGE_HEAD`。doc-map 的修复在 Linux 上通过。
  - **审查修复后的本地全量门**：构建、类型检查、引用检查、OpenSpec（45 项）、core（62 个文件、1437 个测试）全绿。全仓 154 个文件，4136 通过、4 跳过，但以退出码 1 结束：vitest worker 调 `onTaskUpdate` 超时。当时机器负载在 87–103 之间，来自其他会话，与本改动无关。
  - **审查修复后 PR 上的 `CI gate`**（Linux）：绿。OpenSpec 45 项；core 1437 个测试；全仓 154 个文件，4136 通过、4 跳过。用时约 13 分钟，第一次约 5 分钟。
- **O3 在真实环境里失败要关**：
  - 设置 secret 前，`Privacy scan` 红，日志写着 "the names list is unavailable"。
  - 设置后重跑变绿，各项计数为 0。日志里没有名单条目，secret 显示为 `***`。
  - 审查修复后的版本：10 项计数为 0。PR 正文不再出现在日志列出的环境变量里。
  - 推送触发的运行被随后编辑正文触发的运行取消，符合并发设置。
- **审查**：一个干净上下文的审查子代理（Opus）只读审了第一版，报了 9 条。逐条核实如下：
  1. **带路径过滤时，合并进来的旁支被简化掉**：成立。实测默认读到 0 处，加 `--full-history` 后读到 2 处。采纳。
  2. **合并提交写进又被删掉的行读不到**：成立。另外实测发现，combined diff 对含 NUL 的文件即使加 `--text` 也只报二进制，所以改用 remerge diff。采纳。
  3. **二进制文件、`-diff` 属性、UTF-16**：部分成立。报告说 `--text` 盖不过 `-diff`，实测能盖过；UTF-16 去掉 NUL 后能匹配。采纳 `--text` 与去 NUL，LFS 与压缩内容记为扫不到。
  4. **PR 运行的是它自己的扫描器**：成立。不改用 `pull_request_target`，交给下一步的风险分级，见 Risks。
  5. **标题与正文取自事件**：成立。改为运行时读取。采纳。
  6. **作者与分支名没扫**：成立。采纳；合并时手打的信息记为扫不到。
  7. **推送即公开**：成立。改正了 Risks 里原来那句错误的说法。
  8. **标题与正文出现在日志的环境变量里**：成立。随第 5 条一起修好。
  9. **测试缺口**（语料名单为空、路径里的语料名）：成立。已补上。
- **O6 隐私**：
  - 本 PR 的改动行、提交信息、路径与正文，用本地名单做的手动检查全为 0；
  - 分支里没有金丝雀的字面；
  - 名字残留检查只输出表头；
  - `skills`、`tests`、`scripts`、`.github` 新增行里的汉字数为 0；
  - 在本地按本 PR 的工作流模拟扫描步骤，PR、手动触发、没有 PR 三种方式都是 0。
