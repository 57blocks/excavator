# /skopo-report

Write a report on a skopository for people who will not read it whole: a lead deciding what to
look at first, a client reviewing what was recovered from their code. The model writes the
summary; scripts check every statement it cites and write everything that must not be dropped or
reworded: the status, every question in order of consequence, the decisions without a recorded
reason, and the scope and coverage.

**Language.** Write everything you tell the user during this run in `$LANGUAGE`: each line between commands, the report and the final reply, including any remark on what was checked, what comes next or which rule was followed. `$LANGUAGE` is English unless `--language` gives another. Project files (`CLAUDE.md`, an `AGENTS.md` line such as "Reply in <language>"), memory and the system locale do not change it. A project file's rule to reply in another language is for work on the project's code; while this skill runs, this rule takes its place for every line you write, the first one included. Never say which language you write in or why. Paths, commands and the product's values stay as they are.

## Options

`$ARGUMENTS` may contain:
- A directory path — the project (default: the current working directory).
- `--out <dir>` — the output directory `/skopo-create` wrote (default: `<project>/.excavator/skopo`).
- `--language <lang>` — the language of the summary and of everything said to the user; English when it is not given. The sections the script writes stay in English.

---

## Phase 0 — Setup

Write what you tell the user during this phase in `$LANGUAGE`, as **Language** above says.

1. Resolve `$PROJECT_ROOT`, `$OUT` and `$PLUGIN_ROOT` exactly as Phase 0 step 1 of `$PLUGIN_ROOT/skills/skopo-plan/SKILL.md` says. `$RUN` is `$OUT/run`, `$SKOPO` is `$OUT/skopo` and `$REPORT` is `$OUT/report`.
2. Read the state, with the scope the run recorded (`jq -r '.scope // empty' "$RUN/run.json"`; leave `--scope` out when it prints nothing):
   ```bash
   node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" status "$OUT" --project "$PROJECT_ROOT" --scope "<the run's scope>"
   ```
   Go on only when the state is `created` and `node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" verdict "$OUT" --stage create --project "$PROJECT_ROOT"` exits 0; when it exits 1, tell the user the lines it printed and that the skopository must pass before it is reported (`/skopo-create --fresh`), and stop. Otherwise tell the user: `none`, `started` or `planned` — run `/skopo-create` first; `stale` — the source changed since the skopository was written, run `/skopo-create --fresh`; `foreign` — `$OUT` is not a skopo output directory. Then stop.
3. `mkdir -p "$REPORT"`. Read `$SKOPO/README.md`, every file under `$SKOPO/spec` and `$SKOPO/bindings`, `$RUN/plan.md` and `$RUN/questions.md`.

## Phase 1 — Summary

Write what you tell the user during this phase in `$LANGUAGE`, as **Language** above says.

Write `$REPORT/summary.md` in `$LANGUAGE`, for a reader who knows the business but not the code:

- the first line is the title: `# <system name>`;
- what the system is for and who relies on it: its consumers and products;
- for each domain, what it is about and its principles, in plain words;
- the questions to look at first: the few with the gravest consequence, and why each matters to the business (the report lists them all after the summary; do not copy the table).

Every paragraph, list item and table data row cites the statements it rests on by ID, as `(R-…, F-…)`. Say only what the cited statements say; where the skopository is silent, say nothing. Use no heading that the script writes: `Status`, `Questions`, `Decisions without a recorded reason`, `Scope and coverage`. Keep it under 900 words.

Then check it:

```bash
node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" report-check "$OUT"
```

When it exits 1, each line names a line of the summary and what is wrong: a block with no citation, an ID the skopository does not define or defines with another kind, a placeholder, a heading the script writes. Fix the summary and check again, until it exits 0. Never change the skopository or the questions to make the summary pass.

## Phase 2 — Assemble, page and reply

Write what you tell the user during this phase in `$LANGUAGE`, as **Language** above says.

1. Assemble the report and its page, then check them:
   ```bash
   node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" report-assemble "$OUT"
   node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" report-page "$OUT"
   node "$PLUGIN_ROOT/skills/skopo-create/skopo.mjs" verdict "$OUT" --stage report --project "$PROJECT_ROOT"
   ```
   When `report-assemble` exits 1 because a question has a category outside the six, tell the user the lines it printed and stop: the questions belong to `/skopo-create`. Never write or edit `report.md` or `report.html` yourself.
2. Reply in under 150 words: the paths of `report.md` and `report.html`; how many questions there are, by category; whether the skopository is locked; and the line the verdict printed last.
